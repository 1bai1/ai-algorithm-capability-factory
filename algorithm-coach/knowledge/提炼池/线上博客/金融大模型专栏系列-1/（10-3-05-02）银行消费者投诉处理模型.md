# （10-3-05-02）银行消费者投诉处理模型

## 筛选结论
不适用 —— 用预训练 Transformer 的隐藏状态做投诉文本 11 分类（浅层逻辑回归 + 微调两条路线），属纯 NLP 文本分类；只有"特征提取→分类器→留出集评估→混淆矩阵"的通用骨架可顺带参考。

## 核心内容
- 思路是两段式：先把文本经 Transformer 编码得到的隐藏状态（hidden_state）当特征，再接一个浅层分类器；该篇即从保存隐藏状态开始。
- 数据落盘：corpus_hidden["train"] 与 ["validation"] 导出为 pandas 后分别存 training.df / validation.df；标签整数经 `corpus["train"].features["label"].int2str` 反查为标签名。
- 特征与标签：`X = np.stack(df['hidden_state'])`、`y = np.array(df['label'])`；标签共 11 类（debt collection、mortgage、credit card、credit reporting、student loan、payday loan、prepaid card、money transfers、bank account or service、virtual currency、other financial service）。
- 基线：LogisticRegression(max_iter=2000)，训练准确率 0.807、验证准确率 0.772，训练耗时约 5 分钟（据此判断迭代上限足以收敛）。
- 微调路线：将数据格式切到 torch、用 Hugging Face Trainer + TrainingArguments 训练预训练模型，验证集规模 2901；输出 logits 形状 (2901, 11)，用 `np.argmax(..., axis=1)` 贪心解码成类别。
- 模型持久化：`joblib.dump(lr_clf, 'classifier.joblib.pkl', compress=9)`；训练前后用 `torch.cuda.empty_cache()` 释放显存。

## 可复用要点
- 通用评估范式可迁移：训练集/验证集分离 → 同时报告训练与验证准确率判断过拟合（此处 0.807 vs 0.772）→ 混淆矩阵逐类看性能 → joblib 压缩保存模型。这套骨架同样适用于涨跌方向等分类任务。
- "预训练模型输出 embedding + 浅层分类器"作为低成本基线，再与微调模型对比，是小样本场景的常见做法。
- 无金融特征、无时序切分、无回测指标，与量化预测无共享内容。
