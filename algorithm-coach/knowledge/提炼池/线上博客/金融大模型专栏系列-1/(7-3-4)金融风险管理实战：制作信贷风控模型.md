# (7-3-4)金融风险管理实战：制作信贷风控模型

## 筛选结论
部分保留 —— 业务是 Kaggle 信贷违约概率预测（横截面二分类），与 A 股价格预测无直接关系；但基线/集成模型的训练与验证骨架、特征重要性做法属于通用环节，供本项目"模型训练与评价"参考。

## 核心内容
- 数据规模：训练 307511×240、测试 48744×240，目标 TARGET 为是否违约，输出 0-1 概率。
- 预处理顺序：删除目标列 → 中值填充缺失值 → MinMaxScaler 归一化到 [0,1]，先 fit 训练集再 transform 测试集。
- 基线模型：逻辑回归 C=0.0001（压低 C 抑制过拟合），取 predict_proba 第二列作为违约概率。
- 升级模型：100 棵随机森林（random_state=50），输出概率并提取特征重要性；估计提交得分约 0.678。
- 特征工程对照实验：多项式特征与原始特征得分完全相同（0.678），说明该组工程特征无增益；手工领域特征进入前 15 重要特征。
- LightGBM 用函数 model() 封装 5 折交叉验证，独热编码后按列 inner 对齐训练/测试，验证集 100 轮无提升即早停，输出提交文件、特征重要性与 CV 指标。
- 特征重要性集中在 EXT_SOURCE 系列与 DAYS_BIRTH，少数特征贡献显著。

## 可复用要点
- 训练验证骨架：KFold(5) + ROC AUC 逐折记录 + 早停 + 特征重要性导出 + 各折预测汇总为提交，可套用到涨跌方向、风险事件等任何金融二分类。
- 缺失值中值填充 + [0,1] 归一化的顺序与 fit/transform 边界（只在训练集 fit）。
- 特征重要性函数 plot_feature_importances(df)：按重要性降序、归一化到总和为 1、画水平条形图。
- 模型选择策略：逻辑回归当基线，随机森林/LightGBM 作升级，用同一验证协议对照，并显式做"加特征 vs 不加特征"的消融。
- 早停口径：验证指标 100 轮未改善即停止，最佳迭代从 208 到 237 不等。

## 关键实现
- sklearn：Imputer(strategy='median')、MinMaxScaler(feature_range=(0,1))、LogisticRegression(C=0.0001)、RandomForestClassifier(n_estimators=100, random_state=50, verbose=1, n_jobs=-1)、KFold、roc_auc_score。
- LightGBM：import lightgbm as lgb，函数 def model(features, test_features, encoding='ohe', n_folds=5)，返回 (submission, feature_importance, metrics)。
- 输出文件：log_reg_baseline.csv、random_forest_baseline.csv、random_forest_baseline_engineered.csv、random_forest_baseline_domain.csv、baseline_lgb.csv，字段为 SK_ID_CURR + TARGET。
- 原文多处代码块截断（如 plot_feature_importances 只给前半段）。

## 数据与假设
- Kaggle Home Credit 类信贷数据：app_train / app_test 两表，键 SK_ID_CURR，标签 TARGET；静态横截面，无时序结构。
- 假设：中值填充与归一化足以处理缺失和量纲；以 ROC AUC 衡量模型排序能力；不做时间切分。

## 局限与风险
- 横截面信贷分类，不能迁移为价格/收益预测；无时序交叉验证，存在用未来样本训练的风险。
- Imputer 已被新版 sklearn 移除，代码不能直接运行；多处代码截断。
- "领域特征得分会有进步"只有定性描述，无具体分数与多次随机种子验证；随机森林与 LightGBM 的 AUC 差异也未做显著性检验。
