# （5-3）制作贵州茅台的ARCH模型

## 筛选结论
保留 —— 唯一一篇完全基于 A 股真实数据（贵州茅台 + 大盘指数）的波动率与价格建模实例，数据接口与流程可直接复用；但"ARCH 模型"名不副实，需按局限取用。

## 核心内容
- 数据获取用 Tushare：pro.daily(ts_code='600519.SH', start_date='20200101', end_date='20230901') 拉茅台日线，字段含 open/high/low/close/pre_close/change/pct_chg/vol/amount。
- 另用 Tushare 取同区间的大盘指数（Market_index）与成交量（Trading_volume）作为市场特征，按日期对齐（个股的 trade_date 改名为 Date）后与个股数据合并。
- 所谓 ARCH 模型实际只是 PyTorch 的单个 nn.Linear 对日收益率做线性变换，用 MSE 损失、Adam 优化器训练 10000 轮，每 100 轮打印损失，再把输出当作"预测波动性"画曲线。
- 单层线性模型损失降到约 1e-16；加入大盘指数特征后损失反而扩大到 2046 量级，原文据此判断"加入大盘指数特征使性能变差"。
- 第三个模型改用两份数据预测收盘价，损失从 2.3e-3 收敛到 1e-6 量级，测试集 MSE 为 2.3159，并画出真实收盘价与预测收盘价的对比图。
- 原文提醒：MSE 小不等于模型可靠，还需结合实际场景进一步评估。

## 可复用要点
- A 股数据接口模板：Tushare pro.daily 的调用参数与返回字段可直接进入我们的数据层；大盘指数与市场成交量可作个股模型的辅助特征，前提是按日期对齐并做量纲统一。
- 波动率预测的正确做法是给波动率设标签（收益率平方、滚动标准差）或用 GARCH 族，而不是用 MSE 拟合收益率本身；本篇可作为代码生成器的反例约束。
- 多源特征合并时量纲差异大的列必须先标准化（指数在 3000 量级），否则训练损失会失控（第二模型 2046 量级的损失即为例证）。
- 结果报告最小集合：训练损失曲线 + 测试集 MSE + 预测与真实值对比图。

## 关键实现
- 文件划分：maotai.py（Tushare 取数并落盘 CSV）、economic.py（取市场指数与成交量）、maofeng1.py（单层线性波动率模型）、maofeng2.py（加大盘指数特征）、maofeng3.py（收盘价预测模型）。
- 依赖 tushare、torch（nn.Linear / nn.MSELoss / torch.optim.Adam）、pandas、matplotlib；训练循环 10000 轮、每 100 轮打印一次损失。
- 因变量构造：pct_change() 计算日收益率并删去 NaN 行后转成 PyTorch 张量。

## 数据与假设
- 标的贵州茅台 600519.SH 日线，区间 2020-01-01 至 2023-09-01；市场指数与成交量同区间。
- 假设收益率序列的波动性可由该模型拟合，且大盘指数特征对预测有增益。

## 局限与风险
- 名为 ARCH 实为单层线性回归，没有条件方差方程，模型输出不具备波动率的物理含义。
- 损失降到 1e-16 意味着线性输出与目标几乎完全重合（近乎恒等映射），这不能证明模型学到了波动率；原文把它当作拟合极好的证据。
- 第二模型损失暴增最可能源于大盘指数量纲未处理（原文未写标准化步骤），原文却把结论归为"加入该特征无益"，属归因错误。
- 未说明训练/测试切分方式，除 MSE 外无其他指标；股价预测 MSE=2.3159 未与"上一日收盘价"基线对比，无法证明有预测能力。
- 全文无平稳性检验、残差检验与滚动回测，与真实波动率预测和风险度量的要求差距较大。
