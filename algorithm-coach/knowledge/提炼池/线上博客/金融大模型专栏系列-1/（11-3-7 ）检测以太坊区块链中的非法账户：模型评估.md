# （11-3-7 ）检测以太坊区块链中的非法账户：模型评估

## 筛选结论
部分保留 —— 项目领域（区块链非法账户检测）不在我们的范围内，但本篇内容是通用模型评估流程：交叉验证调参、训练/测试双端指标、ROC 与 PR 曲线、多采样技术对比，可直接迁到回测与评价指标环节。

## 核心内容
- 定义统一的评估函数 model_fit_evaluation2，一次完成调参、预测、指标输出和两种曲线绘制；对 5 个"模型 × 采样技术"组合重复调用（GradientBoosting / LightGBM / CatBoost，分别配 oversampling 或 SMOTE）。
- 调参用 RandomizedSearchCV：cv=10、scoring='roc_auc'、n_jobs=-1、random_state=23。
- 指标清单：AUC、Accuracy、Sensitivity（=Recall=TPR）、Specificity、Precision、F1、混淆矩阵，训练集与测试集分别输出。
- 示例结果：GradientBoosting(learning_rate=0.5, n_estimators=50) 交叉验证 best score 0.9994；CatBoost+SMOTE 测试集 AUC 0.9802、Accuracy 0.9827、Precision 0.9439、Recall 0.9758、Specificity 0.9846、F1 0.9596，混淆矩阵 TN=766、TP=202、FP=12、FN=5。
- 原文明确提醒：训练集性能远高于测试集，需警惕过拟合。
- 除 ROC 曲线外还绘制测试集 Precision-Recall 曲线，用于类别极不平衡时补充评估。

## 可复用要点
- 评估函数骨架：RandomizedSearchCV 选参 → 用 best_estimator_ 在训练集和测试集上分别 predict / predict_proba → 输出 AUC 与全套分类指标 → 画 ROC 与 PR 曲线。
- 采样敏感性协议：同一模型在 oversampling 与 SMOTE 下各评估一遍再选优；A 股涨跌标签不平衡时可直接套用该对比方式。
- 回测报告字段模板：AUC 主指标 + Accuracy/Sensitivity/Specificity/Precision/F1 + 混淆矩阵四元组（TN/TP/FP/FN）。
- 用 time.time 记录每轮评估耗时，用于评估调参成本。
- 随机种子固定为 23。

## 关键实现
- model_fit_evaluation2(model_model, params, X_train, y_train, X_val, y_val, algo=None, sampling=None)。
- 调用示例：model_fit_evaluation2(model_GB, params_gb, X_train_ro, y_train_ro, X_test, y_test, 'GradientBoosting', 'oversampling')。
- 依赖 sklearn（RandomizedSearchCV、metrics、precision_recall_curve）与 matplotlib；自定义函数 draw_roc 与 model_metrics 只给出调用，实现未展示。
- 注意：计算 AUC 时传入的是 predict 的硬标签（roc_auc_score(y_train, y_train_pred)），与绘制 ROC 使用概率的做法不一致。
- 源码与数据集通过百度网盘链接提供，原文未列字段清单。

## 数据与假设
以太坊账户级特征数据集（特征构造见前文，本篇未展开）；训练使用重采样版本（X_train_ro / X_train_smote），测试集保持原始分布；10 折交叉验证；函数形参名虽为 X_val/y_val，实际传入的是 X_test/y_test，评估在测试集上完成。

## 局限与风险
评估函数直接用测试集做模型筛选，若再据此选模型会造成测试集泄漏（原文未讨论）；AUC 用硬标签计算与概率版 ROC 语义不一致；约 0.98 的 AUC 在该任务上异常高，原文未排查特征泄漏或标签泄漏；随机搜索的参数空间与候选数未给出，结果难复现；区块链账户二分类与 A 股价格预测的时序非平稳性差异大，迁移时需改为时序切分与滚动验证。
