# （27-3）基于深度强化学习（DRL）的比特币交易系统：比特币交易数据集

## 筛选结论
保留 —— 给出了一个可用的小时级加密 OHLCV 数据集规格（来源、字段、缺口处理）以及一套现成的技术指标特征工程（多周期 EMA 加波幅比率及其 EMA），数据接口与特征构造两层都能直接复用。

## 核心内容
- 数据集覆盖 2017-01 至 2023-10 的加密货币市场，小时级频率，含 OHLCV 与每小时交易笔数。
- 覆盖 34 种代币（BTC、ETH、DOGE、SOL 等），可用于多标的或组合类策略。
- 三个数据文件分工：crypto_data.csv 为清洗后主数据（缺失小时占比低于 0.015%）；crypto_force.csv 为合并外部源补缺的中间稿；cryptotoken_full.csv 为各代币原始数据合并的全集。
- 数据来源：主要经 Binance API 获取，缺失时段用 Kraken 与 Poloniex 的市场数据补齐。
- 数据清理做了两件事：修正多余小数位的日期格式（如 ".000"、".874"）与填补缺失小时。
- 实际实验只取 BTC 一个标的，区间截取 2020-08-17 04:00 至 2023-10-19 23:00。
- 特征工程：对收盘价生成 13/25/32/100/200 周期 EMA；定义波幅比率 vol_close=(high-low)/close，再对其取 3/6/12 周期 EMA（小时频率下对应 2/4/8 小时）；星期字段映射为 1–7 的数值。
- 处理后落盘 data_featured.csv，并丢弃 symbol 与 token 两列（原文中 set_index('date') 被注释，日期仍为普通列）。

## 可复用要点
- 数据字段：date、symbol、open、high、low、close、volume usdt、tradecount，另可由时间派生 hour 与 day（星期）。
- 小时级数据的星期编码：Monday=1 至 Sunday=7，转数值后可直接入模。
- 一组现成的特征参数：EMA(close) 取 {13,25,32,100,200}；波幅比率 (high-low)/close 及其 EMA{3,6,12}（对应 2/4/8 小时平滑）。
- 多标的筛选套路：按 token 字段加日期区间双重条件切片，并先深拷贝副本，避免污染原始数据框。
- 缺口处理思路：主源（Binance）缺失时用其他交易所（Kraken/Poloniex）补齐，并记录缺失率量级。

## 关键实现
- `pd.read_csv('crypto/crypto_data.csv')` 载入；切片条件 `(data_df['token']=='BTC') & (data_df['date']>=start_date) & (data_df['date']<=end_date)`。
- EMA 生成：`data_df['close'].ewm(span=N).mean()`；vol_close：`(data_df['high']-data_df['low'])/data_df['close']`，其 EMA 用 `ewm(span=N, adjust=False).mean()`。
- 收尾：`pd.to_datetime(data_df['date'])` 转时间类型，`drop(columns=['symbol','token'])` 去冗余列，`to_csv('data_featured.csv', index=False)` 落盘。
- 依赖仅 pandas。

## 数据与假设
- 标的：初筛 34 种加密代币，本步骤只用 BTC。
- 频率：小时；全量区间 2017-08-17 04:00 至 2023-10-19 23:00，实验用 2020-08-17 起。
- 成交量以 USDT 计价，交易笔数为小时聚合值。
- 假设：不同交易所的数据可直接拼接补齐（未说明价格口径对齐与去重方式）。

## 局限与风险
- 跨交易所拼接可能引入价格口径不一致与重复小时，原文只说"确保一致性"，未给出校验方法。
- 特征全部为价格衍生指标，本篇未做缺失值填充、异常值处理与标准化。
- 星期/小时等日历特征对 7×24 连续交易的加密货币是否有预测价值，原文未验证。
- 未做特征与标签的相关性、平稳性等分析，特征有效性未经检验。
- 代码中 astype/set_index 被注释，说明流程未经清理，日期列格式在后续建模中需再次确认。
