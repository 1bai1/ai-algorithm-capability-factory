# （15-3）基于时间序列预测的比特币自动交易系统：数据探索分析

## 筛选结论
部分保留 —— 属于我们"数据获取与清洗"环节，但本篇只做了最基础的加载与体检，唯一有沉淀价值的是数据集规格与"无需清洗"这一结论。

## 核心内容
- 数据加载：从 `../input/bitcoin/BTC-USD.csv` 读入为 BTC_data 数据框。
- 数据结构：7 列，Date（object 类型，需后续转换）、Open、High、Low、Close、Adj Close（float64）、Volume（int64）。
- 规模：2587 条记录，即约 7 年日度数据，起始于 2015-01-01。
- 数据质量：逐列缺失值统计全为 0，原文据此判定不需要数据清洗。
- EDA 手段仅限于五个基础调用：head 看结构、tail 看最新时点、info 看类型与非空计数、describe 看分布、isna().sum() 数缺失。

## 可复用要点
- 时序数据入库前的体检清单：head/tail 看首尾、info 看类型与空值、describe 看分布、isna().sum() 逐列数缺失。
- 日频 OHLCV 的标准列名：Date, Open, High, Low, Close, Adj Close, Volume（与 yfinance 输出一致）。
- 确认无缺失后可直接跳过清洗进入特征与建模阶段（本例即如此）。

## 关键实现
- `BTC_data = pd.read_csv("../input/bitcoin/BTC-USD.csv")`，随后依次调用 `head()` / `tail()` / `info()` / `describe()` / `isna().sum()`。
- 依赖仅 pandas；无自定义函数、无超参数。

## 数据与假设
- 标的：比特币（BTC-USD），日频。
- 时间范围：2015-01-01 起，共 2587 个交易日。
- 字段：开高低收、复权收盘、成交量。
- 假设：CSV 自带数据可直接使用，无需清洗与对齐。

## 局限与风险
- 未检查重复日期、时间连续性、节假日缺口与异常值（如异常单日成交量），"无缺失"不等于数据可用。
- Date 仍是 object 类型，未做 to_datetime 转换与排序，后续步骤直接使用会出错。
- 未做任何可视化（价格/成交量走势、收益率分布），无法发现结构性断点。
- 未讨论收益率平稳性、自相关等时序建模前的必要检验。
