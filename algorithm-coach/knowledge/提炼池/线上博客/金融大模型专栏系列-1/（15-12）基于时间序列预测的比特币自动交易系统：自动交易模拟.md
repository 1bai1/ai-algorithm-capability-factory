# （15-12）基于时间序列预测的比特币自动交易系统：自动交易模拟

## 筛选结论
保留 —— 提供了一个逐日重估模型的事件驱动回测循环（run_simulation）以及阈值、模型阶数的对比实验方法，对回测引擎与策略参数搜索直接有用。

## 核心内容
1. 模拟函数逐日遍历收益率序列（跳过前 14 期），持仓则当日卖出结算收益，空仓则按条件决定买入，并逐笔记录 (买卖方向, 日期, 收益) 事件。
2. 每到一个新日期都用截至前一日的数据重新拟合 ARIMA，再预测下一期收益；预测值超过阈值才开仓，属典型的滚动重估（walk-forward）回测。
3. 阈值实验结论：ARIMA(1,1,1) + 阈值 0.01 时，1000 美元增至约 1060.22 美元；ARIMA(1,0,0) + 阈值 0.001 取得 44% 回报。
4. 纯规则对照：“上一个收益为正就买入”（last 策略）最终约亏损 5%，说明简单动量规则在比特币上无效。
5. 用 1000 次重复模拟的最终金额分布图（标注均值线与初始金额线）来呈现策略的风险收益分布。
6. 高阶模型代价明显：ARIMA(5,0,5) 每次重估都需拟合，169 次迭代耗时约 2 分钟，且频繁报 Schur decomposition solver error。

## 可复用要点
- 回测循环模板：按日遍历 → 持仓先平仓结算并更新资金 → 空仓则用截至当前的数据重新拟合 → 一步预测 → 与阈值比较决定开仓 → 记录事件与资金曲线。
- 开仓规则：预测收益 > 阈值才买入，阈值需网格搜索（原文试过 0、0.001、0.005、0.01 等取值）。
- 评价方式：最终资金额 + 多阈值横向对比 + 多次模拟的资金分布。
- 参数经验：提高 ARIMA 阶数并不改善效果，反而使重估成本剧增且数值求解不稳定（Schur 分解报错）。

## 关键实现
- 函数：run_simulation(returns, prices, amt, order, thresh, verbose=False, plot=True)。
- order 支持三种形态：tuple 表示 ARIMA 阶数（如 (1,1,1)、(1,0,0)、(5,0,5)）、字符串 'last' 表示“上一期收益为正则买”、float 时把 thresh 置空。
- 依赖：statsmodels 的 ARIMA(...).fit() 与 model.forecast()[0]；tqdm 进度条；warnings 忽略；matplotlib/seaborn（distplot）绘图。
- 循环从 returns.iloc[14:] 开始，预留 14 期初始窗口；拟合异常用 try/except 捕获并打印错误。

## 数据与假设
比特币日频价格与收益率，区间 2021-04-01 至 2021-10-01，共 169 个交易日；初始金额 1000（部分实验用 100）。假设无手续费与滑点、按日收盘价全额成交、只有满仓与空仓两种状态。

## 局限与风险
- 样本仅 6 个月、169 个点，且落在比特币剧烈波动区间，单次模拟的 44% 回报不具统计意义。
- 无交易成本、滑点、止损与仓位管理，原文自己也提示实盘需要更复杂的模型与风控。
- 每期重估但未做收敛性与平稳性检查，Schur decomposition 报错说明部分拟合结果不可靠，原文未说明异常后的实际行为。
- 1000 次“模拟”未说明随机性来源（ARIMA 与规则逻辑均为确定性），分布图的统计意义存疑。
