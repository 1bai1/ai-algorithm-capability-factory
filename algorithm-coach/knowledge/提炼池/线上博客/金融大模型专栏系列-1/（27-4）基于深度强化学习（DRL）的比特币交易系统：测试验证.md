# （27-4）基于深度强化学习（DRL）的比特币交易系统：测试验证

## 筛选结论
部分保留 —— 给出了 DRL 交易系统状态空间的特征清单（多周期 EMA + 波动率 EMA）可复用；但本篇的"验证"把训练集直接当验证集，验证设计不成立。

## 核心内容
- 验证数据集直接用训练集赋值（val_data = train_df）并重置索引，共 27812 条小时级记录、18 列。
- 特征列：date、open、high、low、close、volume usdt、tradecount、hour、day，以及 ema_13/25/32/100/200、vol_close、vol_close_ema_3/6/12。
- 用 info() 与 head() 检查字段类型（1 个 datetime、13 个 float、4 个 int）与缺失，全部字段无空值。
- 数据自 2020-08-17 04:00 起按小时连续采样；首日各周期 EMA 初值相同，随后逐步分离，符合 EMA 递推特征。
- 测试环节：加载预训练 PPO 代理并在环境中按回合执行"选动作 → 与环境交互 → 更新状态/奖励/完成标志"，按间隔打印每回合最终奖励与总交易次数，运行在 CPU 上。

## 可复用要点
- 特征模板：小时级 OHLCV + 成交笔数 + hour/day 时间特征 + 5 个 EMA 周期（13/25/32/100/200）+ 波动率序列及其 3/6/12 周期 EMA，可直接作为 A 股日内/日频强化学习环境的状态空间起点。
- 环境交互约定：动作输出后环境返回状态、奖励与完成标志，按回合统计累计奖励与交易次数作为策略表现指标。
- 时间编码用 hour/day 两个整型字段，是周期特征最简做法。

## 关键实现
- 关键语句：val_data = train_df；val_data.reset_index(drop=True)；val_data.info()；val_data.head()。
- 其余为 PPO 代理加载与多回合 rollout 循环，输出示例：Using cpu device / Step: 1 / Open Position: 1。
- 依赖 pandas 与某种 PPO 强化学习实现（原文未给库名、超参、奖励函数与网络结构）。

## 数据与假设
- BTC 小时级行情（含 volume usdt、tradecount 字段），27812 条，起点 2020-08-17 04:00，无缺失值。
- 假设该组价量特征足以描述市场状态，训练好的 PPO 代理可直接在新环境复用。

## 局限与风险
- 直接把训练集当验证集（val_data = train_df），没有样本外数据，无法评估过拟合；原文却称之为"验证数据集"。
- 未给出 PPO 超参数、奖励函数、初始资金与手续费假设，也没有累计收益、夏普等绩效指标，只有奖励与交易次数。
- 测试输出被截断且代理表现无结论，无法判断该 DRL 策略是否有效。
- vol_close 的具体口径（已实现波动率还是其他）原文未说明；特征全为价量派生，不含跨品种或宏观信息。
