# （11-4-4）比特币价格预测系统：交叉验证

## 筛选结论
保留 —— 讲的是时序预测模型的交叉验证结果如何汇总、按折报告并据此选模型，对应本项目的回测与评价指标环节；内容短但指标口径可直接沿用。

## 核心内容
- 一次 `run_forecast_config` 会产出两类历史评估结果：grid_search（交叉验证）与 backtest（留存测试集），用于查看模型在过去数据上的表现。
- 交叉验证结果用 `summarize_grid_search_results` 汇总成表，关键列是 rank、mean_test、split_test、mean_train、split_train、mean_fit_time、mean_score_time、params。
- 必须同时看均值和各折明细：原文 mean_test_MAPE=60.13，但三折分别是 116.93 / 34.5 / 28.96，折间差异极大，只报均值会掩盖模型对时间段高度敏感这一事实。
- 原文 mean_train_MAPE=73.62 反而高于 mean_test_MAPE=60.13，说明训练折误差同样很大，模型整体精度不足而非过拟合。
- 平均拟合时间 12.56s、平均评分时间 0.86s，可作为模型选择时精度与算力成本的权衡项。
- 结论：交叉验证应按折报告并关注折间方差，而不只看排名。

## 可复用要点
- 评价指标口径：以 MAPE 为主指标；同时对比 mean_train 与 mean_test，判断是欠拟合还是过拟合。
- 模型选择：用 rank_test_* 排名 + 每折分数 + 每折拟合/评分耗时共同决策，兼顾精度与成本。
- 结果组织：把 CV 汇总表以 params 为索引转置，一行一个配置，便于横向比较不同模型配置。
- 折间方差大应触发分段（按市场状态/时间段）评估，而不是直接采信单一均值。

## 关键实现
- 调用：`grid_search = result.grid_search`；`summarize_grid_search_results(grid_search=..., decimals=2, cv_report_metrics=None, column_order=["rank","mean_test","split_test","mean_train","split_train","mean_fit_time","mean_score_time","params"])`；随后将 params 转 str、设为索引并 transpose() 压缩输出。
- 原文片段未包含 import 语句，所用库名与版本未说明；接口名为 run_forecast_config、grid_search、summarize_grid_search_results。

## 数据与假设
比特币价格预测任务；从 split_* 明细看交叉验证为 3 折；频率、时间范围、特征与模型配置原文均未说明；假设历史分段足以代表未来表现。

## 局限与风险
- 未说明训练/测试划分方式与防前视处理，时序交叉验证是否按时间切分无法确认。
- mean_test_MAPE 高达 60 量级（百分比误差远超 50%），原文未讨论该结果是否可接受，也未与基线模型对比。
- 折间 MAPE 在 28.96~116.93 之间波动，结论跨时间段不稳定，原文未做误差来源分析。
- 只有 MAPE 一个指标，缺少方向准确率、交易层面收益/回撤等真正可用于决策的评价。
