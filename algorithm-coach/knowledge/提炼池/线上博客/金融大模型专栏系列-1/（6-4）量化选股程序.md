# （6-4）量化选股程序

## 筛选结论
保留 —— 基于 Tushare 的 A 股全市场选股脚本，给出 5 种均线类策略的规则与参数组合，直接对应本项目的交易策略规则与数据接口环节。

## 核心内容
- 数据源：Tushare，先 ts.set_token + ts.pro_api() 初始化，再用 pro.stock_basic(exchange='', list_status='L', fields='ts_code') 取上市股票列表。
- 行情接口：ts.pro_bar(ts_code, freq, adj='qfq', start_date, end_date, ma=[短,长])，前复权，并可直接返回指定均线列。
- 五种选股策略：均线交叉 Cross、金叉且后续上涨 GoldenCross、K 线站上均线 Suppress、均线单调递增 Trend、均线拐点 Bottom。
- 策略参数化：freq 取 D/W/M，短/长均线周期、回看周期数 n、拐点或金叉后上涨天数 m。
- 结果输出：SaveResult 把命中股票的 ts_code 与 stock_basic 全部字段逐行写入 G:/result/ 下文件。
- 程序含 Menu 菜单选择策略；原文示例以 Bottom 为主线演示主程序流程。

## 可复用要点
- A 股数据接口声明：pro_bar 的 ts_code / freq / adj='qfq' / ma=[短,长] 组合，可用于本项目数据获取模块。
- 策略规则定义（可直接转成信号函数）：Cross(freq,mas,mal,n) = 短均线在长均线之上且过去 n 个周期内出现金叉；GoldenCross 追加"金叉后 m 天内价格上涨"；Suppress(freq,mas,n) = K 线站上均线；Trend(freq,ma_s,n) = 均线连续 n 周期单调递增；Bottom(freq,ma_s,n,m) = 均线出现拐点且拐点后 m 天上涨。
- 示例参数：Cross('W',13,55,2)、GoldenCross('D',8,21,3,1)、Suppress('M',8,10)、Trend('W',55,50)、Bottom('D',55,10,2)。
- 工程细节：遍历全市场时打印进度、取不到数据即 continue、结果按股票逐条落盘。
- Wait(n) 空循环用于降低 API 访问频率，避免限流。

## 关键实现
- 函数：Initial()、Stocklist()、Wait(n)、Menu()、SaveResult(filename,result)、StockDetails(ts_code)、Cross、GoldenCross、Suppress、Trend、Bottom。
- 依赖：tushare、os、time、Queue；未使用任何回测框架。
- 字段：主键 ts_code；StockDetails 遍历 stock_basic 单行输出全部列（制表符拼接）。
- 原文多处代码截断（Cross 主体、菜单与主程序后半段）。

## 数据与假设
- A 股上市（list_status='L'）全市场日/周/月线，前复权；时间窗由 previous=int(now)-30000（now 为 %Y%m%d）到当前日期。
- 假设：均线形态可作为选股信号；不做仓位管理、止损与组合约束。

## 局限与风险
- 原文自述"仅供学习和参考"，全篇无回测、无胜率/收益/回撤指标，信号有效性完全未验证；参数为经验取值，过拟合风险高。
- 时间窗计算存在明显问题：注释称"一年前"，但 8 位日期做十进制减 30000 实际约跨 3 年，且跨月、非交易日偏移不准确。
- Wait(n) 用空循环延时不可靠；逐股串行请求全市场，效率低且易触发 Tushare 限流。
- StockDetails 中 `if i!=None` 无法识别 NaN，可能把缺失值写入结果文件。
