# （5-2）基于人工智能的金融风险建模方法

## 筛选结论
部分保留 —— 属方法论综述（传统风险模型清单 + ML 在风险各领域的应用 + 数据驱动建模九要素），无代码无实证；其中的风险度量工具与建模流程要点对 Agent 的风险与验证环节有参考价值。

## 核心内容
- 传统风险建模方法归为八类：VaR（给定置信水平下的最大可能损失，基于历史数据/正态分布/蒙特卡洛，缺陷是不覆盖极端事件）；风险因子分析（分解市场、利率、信用等因子敞口）；时间序列分析（ARIMA、GARCH）；蒙特卡洛模拟（估计未来价值分布与衍生品风险）；信用评级模型（穆迪/标普/惠誉）；回归分析（多元线性、Logistic）；均值-方差与协方差矩阵估计等申请统计方法；波动率模型（如 Black-Scholes 衡量期权波动率）。
- 总体定位：传统方法在复杂非线性场景下有局限，现代实践是传统方法与 AI/ML 结合使用。
- ML 在风险建模中的九类应用：信用风险评估；市场风险管理（股票/汇率/商品价格波动预测、波动率模型、情感分析）；操作风险（欺诈、异常交易、内部操纵检测）；资产定价（如神经网络估计期权价格）；投资组合优化（含强化学习动态调仓）；风险预警系统（实时监测与即时警报）；洗钱与欺诈检测；量化交易策略（用市场数据制定买卖决策）；文本分析（新闻与社交媒体情绪对市场的影响）。
- 数据驱动风险建模九要素：大规模多来源数据集（市场、财务、宏观、客户交易；来源含交易所、机构内部系统、社交媒体）；数据清洗与整合（缺失、异常、重复）；特征工程（筛选、构造、归一化与标准化）；模型族选择（线性回归、决策树、随机森林、SVM、神经网络按风险类型匹配）；风险类型区分（信用/市场/操作/流动性/法律）；训练与验证（训练集测试集分离评估）；实时监测（新数据自动分析、异常发现、报警）；模型优化（定期更新迭代）；监管合规（透明度、解释性、报告要求）。
- 原文强调 ML 需大量数据与精细调参才能保证性能与鲁棒性，且受到监管关注。

## 可复用要点
- 风险指标可与收益指标并列输出：VaR（置信水平下最大损失，但需明示其不覆盖极端事件）、GARCH 类条件方差与波动率模型、蒙特卡洛模拟得到的净值分布——都是 A 股策略报告可直接挂载的风险度量。
- 建模流程九要素可作 Agent 风险环节的 checklist：数据清洗（缺失/异常/重复）→ 特征工程（归一化、标准化）→ 按风险类型选模型 → 训练与验证严格分离 → 实时监测与异常报警 → 定期重训练 → 保留可解释性以满足合规。
- 与量价预测直接相关的一点：市场风险管理明确把"股票价格预测 + 波动率模型 + 情感分析"列为 ML 的典型用法，可佐证把情绪因子纳入特征体系的合理性。
- 模型选型提示：不存在通吃模型，需按任务类型匹配；组合层面可用强化学习做动态资产配置，与（9-6）的 DRL 组合权重思路互为印证。

## 关键实现
- 无。本篇不含代码、函数或参数；仅出现"用神经网络估计期权定价""用强化学习动态调整资产配置"等方法名，无实现细节。

## 数据与假设
- 无自有数据集，属概念梳理。文中提出数据来源应涵盖交易所行情、金融机构内部系统与社交媒体，数据类型包括市场数据、财务数据、宏观经济指标与客户交易数据。
- 假设风险可按信用/市场/操作/流动性/法律分类并分别建模；ML 模型需足量数据与调参才能具备性能与鲁棒性。

## 局限与风险
- 全篇为罗列式综述，无任何实证结果、指标数值或案例对比，"ML 更优"只是定性断言。
- 未讨论样本切分方式、评价指标、过拟合控制与回测协议——恰是风险模型最易出错、也最需要规范的部分。
- 金融 ML 的常见陷阱（标签泄露、幸存者偏差、非平稳性、交易成本）完全未提。
- 合规与可解释性表述空泛，未给出可操作标准（如需要输出哪些解释性内容）。
- 未涉及中国市场制度差异（涨跌停、T+1、印花税、融资融券约束），迁移到 A 股需补充制度性约束。
