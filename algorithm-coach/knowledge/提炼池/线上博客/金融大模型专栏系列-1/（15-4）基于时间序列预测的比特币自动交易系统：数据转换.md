# （15-4）基于时间序列预测的比特币自动交易系统：数据转换

## 筛选结论
部分保留 —— 比特币时序项目的数据整理步骤（索引化、时间窗截取、统计体检），可作 Agent 数据清洗的最小样板，无建模与策略内容。

## 核心内容
- 把 'Date' 设为索引并从列中删除（`set_index('Date', drop=True)`），便于按日期索引。
- 布尔索引截取 2020-01-01 及以后数据；截取后 761 行，区间 2020-01-01 至 2022-01-30，日频且未见日期缺口（行数与区间日历天数一致）。
- 只做 head / info / describe 三步体检：info() 看各列非空数与 dtype，describe() 看均值、标准差、极值与四分位数。
- 未处理缺失值、未重采样、未构造特征。

## 可复用要点
- 清洗最小模板：日期转 DatetimeIndex → 时间窗过滤（`df[df.index >= '2020-01-01']`）→ info() 校验非空数与 dtype → describe() 看分布。
- 把 info() 行数与预期交易日历长度对照，是发现日期缺口或重复的最低成本手段。

## 关键实现
- 依赖 pandas 三步：`set_index('Date', drop=True)` → `BTC_Data[BTC_Data.index>='2020-01-01']` → `head()/info()/describe()`。

## 数据与假设
- BTC_data 含 Date 与价格数值列（除 Close 外字段未列全）；标的 BTC/USD，日频。假设 Date 已是可比较日期类型且索引无重复。

## 局限与风险
- 未查缺失值、异常值与重复日期，问题会传播到后续建模；起点 2020-01-01 未给理由，样本仅剩 761 天，对深度模型偏少。
- head / describe 输出原文未收录，结论无法核对；未做频率与时区校验。
