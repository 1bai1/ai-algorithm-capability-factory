# 价格序列平稳化（对数、差分与ADF检验）

## 能力说明
对呈指数增长或带趋势的价格序列做对数变换与逐阶差分，并用 ADF 检验定量确认平稳性，为 ARIMA/GARCH/GRU 等要求平稳输入的模型准备数据。解决"把非平稳价格直接喂给模型导致伪回归或学不到东西"的问题。

## 输入契约
- 单变量价格序列（示例为 BTC/USD 的 Close），索引为时间；序列需已按时间升序且无缺口（缺日会使差分含义改变）。
- 序列形态假设：单调上涨/指数增长型（比特币价格即此类），才适合先取对数。
- 差分前需 dropna 去掉产生的首行空值；一阶差分后的序列长度 = 原长 − 1，二阶再 − 1。
- 多序列同频对齐（VAR/协整场景）不在本卡范围。

## 输出契约
- 对数价格序列：把指数趋势线性化，同时缓解方差随价格水平放大。
- 一阶/二阶差分序列：`log_df.diff()`、`log_df.diff().diff()`。
- ADF 检验返回六元组：`(ADF统计量, p值, 使用的滞后阶数, 样本数, 临界值字典, 信息准则值)`。
- 判定规则：p < 0.05 拒绝"存在单位根/非平稳"的零假设（视为平稳）；p > 0.05 不能拒绝（视为非平稳）。临界值随样本量变化，应读返回的临界值字典而不是硬编码。
- 下游可用的收益率口径：`np.log(close).diff() * 100` 后 dropna（百分比对数收益率）。

## 调用方式
```python
import numpy as np, plotly.express as px
from statsmodels.tsa.stattools import adfuller

log_df = np.log(price)                      # 1) 对数线性化
d1 = log_df.diff().dropna()                 # 2) 一阶差分
d2 = log_df.diff().diff().dropna()          # 3) 二阶差分（按需）

stat, p, lags, n, crit, ic = adfuller(log_df)   # 对数价格本身（非平稳）
print(p, crit)                              # 例：0.643，临界值字典
# 一阶差分已平稳即停止，不要继续差分
```
必要前后处理：并列画三张子图（对数价格 / 一阶差分 / 二阶差分）观察趋势与波动；先看图形、再用 p 值确认，把判据写成可断言的检查项；平稳化后再进入模型定阶与训练。

## 关键参数
| 参数 | 含义 | 原文取值/结果 |
| --- | --- | --- |
| 变换 | 趋势线性化 | `np.log` |
| 差分阶数 | 最小够用 | 一阶（实测已平稳，无需二阶） |
| 显著性水平 | ADF 判据 | 0.05 |
| ADF 滞后阶数 | 由默认准则确定 | 输出 4（样本 757） |
| 收益率口径 | 下游建模 | `np.log(close).diff() * 100`，`dropna()` |

## 依赖
numpy（`np.log`）；pandas（`diff` / `dropna`）；statsmodels（`adfuller`）；plotly.express 或 matplotlib（子图观察）。

## 适用条件
- 价格序列呈指数增长/单调趋势（加密货币、长期上涨个股）时，取对数是标准第一步。
- ARIMA、GARCH、VECM 等要求平稳输入或差分输入的模型之前。
- 需要构造对数收益率作为建模序列/标签时。
- 需要把"平稳性"作为建模前体检项固化进流水线时（配合等间隔、自相关、频率一致性检查）。

## 不适用条件
- 已按收益率建模的场景：收益率本身通常已平稳，再取对数差分属于重复处理。
- 含结构突变的序列（加密资产剧烈制度切换）：ADF 容易把结构突变误判为随机趋势，需要分段或加突变检验（原文未给方案）。
- 需要原始价格水平预测的任务：差分/对数变换后必须逆变换才能还原价格，误差会累积，且原文未演示逆变换流程。
- 未做白噪声检验就想下结论"可预测"：平稳只满足建模前提，不代表序列含可提取信号。
- 对多序列协整分析：单变量 ADF 不够，需要残差 ADF 等专门判据。

## 验证状态
已验证（有真实运行数字）：
- 对数价格 ADF 统计量 −1.269、p = 0.643（滞后 4 阶、样本 757）→ 判定非平稳。
- 一阶差分 p ≈ 1.62e-23；二阶差分 p ≈ 1.29e-18 → 两者均平稳，据此选择一阶差分、停止继续差分。
- 原文未做白噪声检验，也未对比"取对数 vs 不取对数再差分"的效果；p 值计算的函数体在原文中被截断，无法逐行复现。
- 另（ARCH/GARCH 篇）给出 `np.log(close).diff() * 100` + dropna 的收益率预处理口径，属同一环节的配套做法，未附独立结果。
