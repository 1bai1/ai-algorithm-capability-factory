# 文本分类开源资源与实现清单

## 能力说明

文本分类落地时的开源实现候选池：按任务形态（短文本、长文档、无分词语料、中文、需要服务化）挑选对应的公开仓库与奠基论文，避免从零重写基线。

## 输入契约

- 任务形态：句子级/短文本分类、长文档分类、字符级或多语言、中文任务、需要在线服务。
- 技术栈约束：是否只接受 TensorFlow 1.x/2.x、PyTorch 或任意实现；是否要求可离线运行。
- 对基线的诉求：只要能跑通拿分数的破冰基线，还是要可改结构的研究级实现。

## 输出契约

- 一份候选实现清单：仓库名、对应模型、适用任务形态、原始论文入口。
- 对每个候选标注的已知风险（维护状态、框架版本、是否需要重写数据管道）。
- 若用于正式基线，需另配一份"按当前技术栈重写"的工作量估计。

## 调用方式

1. 破冰基线：先用 fastText 或 Kim-CNN（CNN_sentence）跑通一个准确率。
2. 按形态升级：长文档 → HAN（文本分类的层级注意力实现）；无分词或形态复杂语料 → Crepe（字符级卷积网络）；需要覆盖多种深度结构 → brightmart/text_classification 合集。
3. 中文任务：从 cnn-text-classification-tf-chinese、text-classification-cnn-rnn（CNN-RNN 中文）、Chinese-Text-Classification 中挑，注意其自带分词/字级预处理是否可复用。
4. 对照原始论文核对结构细节（卷积核尺寸、池化方式等），仓库说明不足时以论文为准。
5. 复用前检查依赖版本与维护状态，预期多数仓库需要重写训练循环与数据管道。

## 关键参数

- 清单未给出任何超参数与精度数字，无可直接引用的参数取值。
- 唯一带任务配置的条目：multi-class-text-classification-cnn-rnn（Kaggle 旧金山犯罪描述，39 类，CNN/RNN + 词向量）。
- 论文入口：arXiv:1408.5882（Convolutional Neural Networks for Sentence Classification）、arXiv:1509.01626（Character-level Convolutional Networks for Text Classification）。

## 依赖

- 仓库多以 TensorFlow 1.x / Torch 实现（2015–2018 年代），与当前主流的 PyTorch / transformers 生态不兼容。
- klassify 依赖 Redis 与 Tornado/React 栈，属于服务化实现而非训练脚本。
- 需要自备数据与分词工具；清单不含数据下载入口。

## 适用条件

- 需要一个快速可跑的传统/深度文本分类基线，且可接受重写部分代码时。
- 中文任务需要现成的 CNN/CNN-RNN 中文实现作起点时。
- 需要追溯 CNN 与字符级 CNN 在文本分类上的原始论文时。

## 不适用条件

- 需要预训练模型（BERT/RoBERTa 类）实现时，本清单不覆盖，应改用 transformers / Hugging Face 生态。
- 对维护状态、License、性能有硬性要求的生产项目，不能直接采用清单中未评估的仓库。
- 需要现成超参与精度参照时，本清单不提供。

## 验证状态

清单本身不含任何实验结果或精度数字，未给出真实运行记录；本卡按"待验证"收录——它提供的是实现入口，不是效果证据。
