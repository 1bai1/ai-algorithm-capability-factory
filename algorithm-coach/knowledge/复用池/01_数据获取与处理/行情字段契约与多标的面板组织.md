# 行情字段契约与多标的面板组织

## 能力说明
定义行情数据入库/入模前的字段契约（列名、主键、频率、复权列）与多标的的组织方式（长表 date+tic 堆叠、宽表 pivot），让下游特征、协方差、横截面因子有统一的数据形状可依赖。

## 输入契约
- 单标的数据帧至少包含：日期列 + OHLCV；有复权价的源必须同时保留原始价与复权价。
- 多标的长表需要两个主键：`date` 与标的代码列（原文出现过三种命名：`tic`、`symbol`、`ticker`）。
- 标的池来源：指数成分股清单（FinRL 内置道指 30 只清单；A 股可对应沪深 300/中证 500），或手写清单（15 只沪市股票、12 只美股、5 只美股+GSPC、34 种加密代币）。
- 日期列在多数来源里是字符串/对象，必须先转 datetime 再排序、再设索引，否则切片与 join 会出错。
- 多标的切片时的字段要求：标的列 + 日期列同时可用，且切片前先深拷贝，避免污染原始 DataFrame。

## 输出契约
- 日线长表（FinRL 风格）9 列：`date, open, high, low, close, adjcp, volume, tic, day`；其中 `tic` 唯一标识标的，`day` 为星期序号。多标的下载示例规模 101,615 行 × 9 列，`adjcp` 为复权收盘价。
- 加密小时级长表：`date, symbol, open, high, low, close, volume usdt, tradecount`，另可由时间派生 `hour` 与星期（Monday=1 … Sunday=7）；覆盖 34 种代币，主数据缺失小时占比 <0.015%。
- A 股经 FinRL 处理后的产物 17 列：`tic, time, index, open, high, low, close, adjusted_close, volume` + 8 个技术指标。
- 原始+复权成对字段的数据字典（对照物，14 列）：`symbol, date, close, high, low, open, volume, adjClose, adjHigh, adjLow, adjOpen, adjVolume, divCash, splitFactor`——把特征来源划成"行情价量 + 公司行为"两类。
- 宽表（date × tic）：用 `pivot_table(index='date', columns='tic', values='close')` 得到价格矩阵，`pct_change().dropna()` 后可用于协方差/相关性；协方差回看窗口示例 252 个交易日（约一年）。
- 索引约定：`set_index('Date', drop=True)`（时间索引）；FinRL 风格用 `df.index = df.date.factorize()[0]`（按日期因子化值作整数索引，便于按日切片）。
- 新闻×行情长表：`ticker, headline, date, eventRet, Close`，示例规模 3142 行 × 5 列、12 只股票。

## 调用方式
```python
# 长表排序与按日索引（FinRL 风格）
df = df.sort_values(['date', 'tic'], ignore_index=True)
df.index = df.date.factorize()[0]

# 宽表：date × tic 的价格矩阵 → 收益率矩阵
px = df.pivot_table(index='date', columns='tic', values='close')
ret = px.pct_change().dropna()

# 多标的按标的+区间双条件切片（先深拷贝）
one = df[df['token'] == 'BTC'].copy()
one = one[(one['date'] >= start) & (one['date'] <= end)]
```
入库/入模前的最小校验：`shape` 打印总行数与列数；`head/tail` 看首尾日期；`info` 看 dtype 与非空计数；确认票池只数（示例 15 只股票对应 15×10+1=151 维状态空间）。多标的加指标后必须再 `fillna` 一次，否则指标首段 NaN 会进入建模。

## 关键参数
| 参数 | 含义 | 原文取值 |
| --- | --- | --- |
| 主键列 | 日期 + 标的 | `date` + `tic` / `symbol` / `ticker`（三种命名并存，需统一） |
| 复权列名 | 复权收盘价 | `adjcp`（FinRL）、`adjusted_close`、`Adj Close`、`adjClose` |
| 日历列 | 星期序号 | `day`（1–7，Monday=1 … Sunday=7） |
| 协方差回看窗口 | 宽表滚动窗口 | `lookback=252` |
| 标的池规模 | 示例 | 30（道指）、15（沪市）、12（美股）、5+指数、34（代币） |
| 列数 | 面板宽度 | 9 列（原始 OHLCV+复权+tic+day）、17 列（+8 指标） |

## 依赖
pandas（sort_values / pivot_table / factorize / set_index）；numpy；FinRL（仅在其 DataProcessor 流程中使用时需要）。

## 适用条件
- 多标的（组合、横截面、强化学习多股票环境）行情组织，需要统一主键与列名时。
- 需要对多标的做协方差/相关性、横截面因子、按日分组状态构造时（长表→宽表 pivot）。
- 需要把行情表与新闻/财务/外部表按 date+ticker 拼接时。
- 数据规模从数千行（单标的 1257~2673 行）到十万行级（101,615 行 × 9 列）都适用。

## 不适用条件
- 单标的、单表的小任务：引入 date+tic 长表与 factorize 索引属于过度设计。
- 需要保留 tick 级或订单簿结构：本组契约止于小时/日频 OHLCV，不含盘口字段。
- 需要跨源一致口径时：不同来源的标的列名（tic/symbol/ticker）与复权列名各不相同，直接拼接会串列，必须先做列名映射。
- 需要处理停牌与交易日历差异：长表按现有行堆叠，不含缺失交易日补行逻辑。
