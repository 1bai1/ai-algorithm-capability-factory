# 文本预处理与分词

## 能力说明
把原始文本（网页、评论、标题）转成分类器可消费的词元序列：解码 → 归一化（大小写、标点）→ 分词
→ 去停用词 / 词干还原。它是向量化之前的一步，直接决定词表里有哪些特征，也决定停用词过滤是否有效。

## 输入契约
- 输入为单篇文档的字符串（或需解码的字节串）；文本文件必须给对 `encoding`（默认 utf-8），
  否则抛 `UnicodeDecodeError`。
- 中文没有空格分词，必须先分词再进向量化器；英文可按空格/标点切分。
- 若使用停用词，停用词表的词形必须与该 tokenizer 的输出形态一致。

## 输出契约
- 词元列表 `list[str]`，交给下游向量化器；`build_analyzer()` 可直接调用来查看切分结果。
- 三层钩子的职责要分清：preprocessor 收全文返回全文（可去 HTML 标签、统一小写）；
  tokenizer 收全文返回词元列表；analyzer 取代前两者，n-gram 拼接与停用词过滤都发生在这一层，
  自定义 analyzer 必须自己补上这两步。

## 调用方式
```python
from sklearn.feature_extraction.text import CountVectorizer

# 默认分析器：\b\w\w+\b（至少两个字母）+ 小写化
vectorizer = CountVectorizer()
vectorizer.build_analyzer()("This is a text document to analyze.")
# ['this', 'is', 'text', 'document', 'to', 'analyze']

# 自定义 tokenizer：传可调用对象，或继承后覆写 build_tokenizer
import re
def to_british(tokens):
    for t in tokens:
        t = re.sub(r"(...)our$", r"\1or", t)
        yield t

class CustomVectorizer(CountVectorizer):
    def build_tokenizer(self):
        tokenize = super().build_tokenizer()
        return lambda doc: list(to_british(tokenize(doc)))

# 外部分词结果（含中文分词）：用空白连接后直接用 str.split
CountVectorizer(analyzer=str.split)

# 词干/词形还原：包一层 tokenizer（原文示例用 NLTK 的 WordNetLemmatizer）
```
- 非 utf-8 文本：显式传 `encoding`，或设 `decode_error` 为 `ignore` / `replace` 容忍；
  也可以先探测编码再解码（原文示例用 chardet，但未打印结果）。

## 关键参数
- `token_pattern`：默认 `\b\w\w+\b`（丢弃单字符词元）；需要单字时改成 `r'\b\w+\b'`。
- `encoding="utf-8"`、`decode_error` ∈ {strict, ignore, replace}。
- `stop_words`：`'english'` 内置表或自定义 list。
- 中文分词粒度（词粒度 vs 字粒度）与分词库：原文只给主张，未给工具与参数。

## 适用条件
- 白空格分词语言（英文等）可直接用默认 tokenizer；有领域词或需要词干归一时自定义 tokenizer/analyzer。
- 已有外部分词结果（包括中文分词）需要接入向量化器时：空白连接 + `analyzer=str.split`。
- 文本编码混杂、需要先修复或容忍时（`decode_error`、ftfy、退回 latin-1）。

## 不适用条件
- 停用词表与分词器不同源必然漏过滤：默认 tokenizer 把 "we've" 拆成 we 与 ve，若表里只有 "we've"
  而没有 "ve"，"ve" 会被当成有效特征留下。
- 风格 / 人格类分类任务不应去停用词：停用词本身携带文体信息。
- 通用停用词表可能删掉对特定任务高信息量的词（原文点名 "computer"），不能无脑套用。
- 改用 `analyzer='char_wb'` 等字符级切分后，词级停用词表不再命中字符片段——原文只说明过滤发生在
  analyzer 层，未展开这种组合，使用时需自行校验。
- 中文部分（分词方法分类、词粒度优于字粒度的主张）来自综述转述，原文未给出可执行实现与验证。
