# yfinance 美股与加密行情接入

## 能力说明
用 yfinance 从 Yahoo Finance 批量或按标的拉取美股、指数、期货、加密资产的日线/周线行情，得到统一的 OHLCV+复权列结构；并给出第三方 REST 行情作为第二数据通道。解决非 A 股标的的行情获取与字段标准化。

## 输入契约
- ticker 形式：单标的字符串（`"AAPL"`、`"GOOG"`、`"LE=F"` 期货、`"BTC-USD"`、指数 `"GSPC"`），也支持 `yfinance` 的多标的下载形式。
- 时间参数：`start` / `end` 字符串（示例 `'1990-01-01'` 至 `'2023-07-28'`、`'2012-05-18'` 至 `'2023-01-01'`、`'2014-09-01'` 至 `'2022-02-1'`）。
- 频率参数 `interval`：日线为默认，周线显式传 `'1wk'`。
- 多标的下载时用 `group_by='ticker'` 控制列层级。
- 备用通道需要第三方 API 的 URL（示例为 CoinCodex 历史数据接口，URL 内直接带日期段与固定参数），接口无鉴权说明。
- 库版本：原文锁定 `yfinance==0.2.3`；未说明 Yahoo 侧限频参数（另见"行情采集容错"卡）。

## 输出契约
- `yf.download` 返回 DataFrame，列为 Open / High / Low / Close / Adj Close / Volume，日期为索引；行数示例：AAPL 周线 1752 行（1990-01-01~2023-07-28）、5 只美股+GSPC 各 2673 行 × 6 列（2012-05-18~2023-01-01）、LE=F 周线 1104 行 × 6 列（2002-03-04~2023-05-29）。
- `yf.Ticker(code).history(start, end)` 返回同类 OHLCV 表；BTC-USD 日线示例：2014-09-01~2022-02-01，以及 2020-01-01~2022-01-31 取到 761 条 `.Close`。
- REST 通道返回 JSON，取 `data` 字段整体转表：`pd.DataFrame(api_data['data'])`。
- 复权：Yahoo 侧同时给 Close 与 Adj Close，是否已复权由来源保证，原文未给复权基准；成交量单位为股。
- 缺失：停牌、节假日导致的缺周/缺日不会补行，取到即缺行，原文未做补齐或对齐。

## 调用方式
```python
import yfinance as yf
# 单标的周线
df = yf.download("AAPL", start='1990-01-01', end='2023-07-28', interval='1wk')
# 多标的逐标的下载（组合/基准研究）
for t in ['GOOG', 'AAPL', 'META', 'AMZN', 'MSFT', '^GSPC']:
    d = yf.download(t, start='2012-05-18', end='2023-01-01', group_by='ticker')
# 加密资产
btc = yf.Ticker("BTC-USD").history(start='2020-01-01', end='2022-01-31').Close
# 备用通道（示例：CoinCodex 历史数据 API）
api_df = pd.DataFrame(json.loads(requests.get(url).text)['data'])
```
必要前后处理：下载后先 `shape` + `head/tail` 核对行数、首尾日期与量纲（示例核对 GOOG 收盘价：2012-05-18 为 14.95、2022-12-30 为 88.73）；多标的要加 ticker 列后纵向拼接；随后按日期索引排序。若两套数据源都可用，用同一标的的价格/成交量偏差做交叉校验。

| 参数 | 含义 | 原文取值 |

## 依赖
yfinance；pandas、numpy；JSON/HTTP 库（备用 REST 通道）；plotly/matplotlib（复核图表）。

## 适用条件
- 美股、美股指数、期货（如 CME 活牛 LE=F 周线）、加密资产（BTC-USD）的历史行情获取。
- 需要约 30 年长历史（1990 年起）做周频收益预测的场景。
- 需要多标的 + 基准指数（5 只股票 + S&P 500）组织组合研究的数据输入。
- 需要第二数据通道做交叉校验、降低单一源风险时（yfinance + 第三方 REST API 组合）。

## 不适用条件
- A 股：Yahoo 无 A 股日线，代码体系、交易日历、复权规则都不同，必须换 Tushare 等本土源。
- 需要保证复权口径可追溯的研究：原文未交代 Yahoo 复权方式与基准日，Adj Close 的变化规则不可控。
- 需要含停牌/缺周已补齐的连续序列：yfinance 直接返回缺行，原文未提及对齐或补缺。
- 需要高频（分钟/秒级）或订单簿数据：本组来源只用到日线/周线。
- 依赖长期稳定的接口：原文示例的第三方 REST 链接带固定参数、无鉴权与限流处理，接口变更即中断；锁定旧版 yfinance 也会在新版接口变化后失效。
