# 异常值检测与重复值清洗

## 能力说明
识别价格/成交量中的离群点与重复记录，并选择剔除、截断、替换或保留调查。解决"脏记录进特征与模型"和"去重不彻底导致重复计数"的问题。

## 输入契约
- 检测对象：OHLCV 价格列、成交量列、表格型数值列；有复权列时应以复权价为准。
- 检测前置：价格必须非负、OHLC 内不得为 0（示例数据里出现过 0 值坏记录）；时间序列应先按日期排序。
- 阈值定义方式（原文出现过的四种）：
  - 均值 ± 标准差（默认倍数原文未给）。
  - IQR 法则：低于 Q1−1.5×IQR 或高于 Q3+1.5×IQR。
  - z-score（GreyKite 的 `ZscoreOutlierTransformer`）。
  - 领域规则：原值显著偏离移动均线即提示异常；OHLC 为 0 直接判坏。
- 重复检测输入：需要能定义"重复"的键。原文只有整行完全匹配的去重实现，没有"同日期+同代码但字段值不同"的判定规则。

## 输出契约
- 处理后序列/表：异常点被替换、截断或整行删除；应有处理前后分布对比图（原文用箱线图）。
- 清洗后的数据集规格示例：金价日频从原始数据剔除 OHLC 为 0 的行后为 5545 行 × 5 列（OHLC+Volume）。
- 去重输出：`cleaned_data.csv`（只保留首次出现的行）。
- 保留异常标记、但不删除的方案（把离群点作为"高风险点"输出）也可行，输入须先标准化。
- 副作用必须显式记录：整行剔除会同时删掉该标的当天的全部其他字段；IQR 截断会改变极端值的量级而保留行数。

## 调用方式
```python
# IQR 整行剔除（表格型）
Q1, Q3 = df.quantile(0.25), df.quantile(0.75)
IQR = Q3 - Q1
df = df[~((df < (Q1 - 1.5 * IQR)) | (df > (Q3 + 1.5 * IQR))).any(axis=1)]

# 均值 ± 标准差阈值 + 用均值替换（不稳健，慎用）
lo, hi = df['Close'].mean() - k * df['Close'].std(), df['Close'].mean() + k * df['Close'].std()
df.loc[(df['Close'] < lo) | (df['Close'] > hi), 'Close'] = df['Close'].mean()

# 领域规则：直接剔除坏记录（价格为 0 等）
df = df[(df[['Open','High','Low','Close']] != 0).all(axis=1)]

# 整行完全匹配去重（无第三方依赖）
seen, rows = set(), []
for r in csv.reader(open('data.csv')):
    key = tuple(r)
    if key not in seen:
        seen.add(key); rows.append(r)
# 表格体检时的常规动作：df.drop_duplicates()
```
必要前后处理：先按日期排序；先统计异常/重复条数再处理（原文未统计缺失与异常规模，导致无法评估影响）；处理完画箱线图/分布图对比。

## 关键参数
| 参数 | 含义 | 原文取值 |
| --- | --- | --- |
| IQR 倍数 | 离群阈值 | 1.5 |
| 均值±标准差倍数 | 离群阈值 | 原文未给出 |
| z-score 阈值 | 离群阈值 | 原文未给出（GreyKite 组件内部默认值未说明） |
| "极大值" 阈值 | 删列条件 | 原文未给出 |
| 去重键 | 记录去重 | 整行完全匹配 |
| 处理方式 | 三选一 | 用均值替换 / 整行剔除 / 截断 |

## 依赖
pandas（`quantile` / `drop_duplicates` / 布尔索引）；numpy；csv（标准库，去重）；matplotlib/seaborn（前后分布对比）；GreyKite（z-score 异常值替换，可选）。

## 适用条件
- 数据里存在明确的坏记录（价格为 0、日期格式串入小数位、跨源拼接的重复小时）时，用规则直接清理。
- 表格型截面数据（信贷等）可用 IQR 1.5 倍法做离群过滤。
- 需要对"异常点"做标注而非删除的场景（风险预警、极端行情研究）。
- 入库前的整行去重（零依赖实现），适合原始记录去重。

## 不适用条件
- 金融厚尾数据：整行剔除离群值会丢掉极端行情样本，均值±标准差阈值本身受离群值影响不稳健；原文示例反而对价格序列用了这类规则。
- 价格序列的"异常"可能正是信号：金融领域的异常值可能代表风险或机会，须先判断是忽略、修正还是调查，不能一律删除。
- 重复定义不止整行时：整行匹配无法识别"同日期+同代码但字段值不同"的重复记录；跨交易所拼接时更会出现价格口径不一致的同小时记录。
- 未统计异常/重复规模就处理：无法评估清洗对样本与分布的影响（原文多篇缺乏这一步）。
- "无缺失"就跳过质检：不查重复日期与异常值，问题会静默传播到建模。

## 验证状态
有缺陷——本卡记录的是原文自己暴露问题的做法：
- （3-1）示例自相矛盾：正文称某段极端波动需处理，但程序输出 `Outliers` 为空、Cleaned Data 与原始数据完全一致，处理实际未生效；均值±标准差被原文自己指出受异常值影响、不稳健，且"极大值/倍数阈值"从未给出。
- （10-2-04）IQR 1.5 倍整行剔除对金融厚尾数据偏激进，会丢掉极端行情样本；其全流程面向静态截面，未在时间序列上验证。
- （15-3）"逐列缺失全为 0，因此不需要清洗"的判定被原文自己批评：未检查重复日期、时间连续性、节假日缺口与异常值。
- 去重实现的效果未验证：集合逐行去重只能处理整行重复；跨交易所拼接的重复小时与价格口径不一致，原文只说"确保一致性"，未给校验方法。
- 可用于定位坏数据的数字：金价日频剔除 OHLC=0 的行后为 5545 行 × 5 列；分钟级数据集"尽力去重但不保证完整性"的来源声明。
