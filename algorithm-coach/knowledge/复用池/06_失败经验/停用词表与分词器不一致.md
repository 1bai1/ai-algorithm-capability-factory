# 停用词表与分词器不一致

## 错误模式
停用词表保存的是原始词形，而向量化器先分词再匹配：分词后词形已经变样，表里没有的残片被当成有效特征
留下。原文给出的判定示例是缩写词 "we've"——默认 tokenizer 把它拆成 we 与 ve，若停用词表里写的是
"we've" 而没有 "ve"，那么 "ve" 会被保留下来进入词表。

## 触发场景
- 停用词表来自第三方清单，未做与该 tokenizer 相同的归一化（小写、去标点、缩写拆分）。
- 中途换了 tokenizer / analyzer（含改用 `analyzer='char_wb'` 等字符级切分），但仍沿用旧的停用词表。
- 停用词过滤与 n-gram 拼接都发生在 analyzer 层，自定义 analyzer 时漏掉或错位了过滤步骤。

## 如何识别
1. 打印向量化后的词表（`get_feature_names_out()`）与停用词表取交集：命中数远小于停用词表规模，
   说明表的词形与分词结果对不上。
2. 抽查分词器输出形态：对含缩写的样本文档跑 `build_analyzer()`，看是否被拆成多个词元。
3. 检查大小写与词干链：停用词表若是 "We've" 而 tokenizer 输出小写词元，同样匹配不上。
4. 留意向量化器的告警：原文说明向量化器会尝试识别并提示部分不一致，但只警告、不阻断——
   有告警就必须处理，不能当噪声忽略。

## 后果
- 停用词没被过滤干净：高频虚词以残缺形态（ve）进入词表，抬高稀疏矩阵非零数，并污染 idf 统计
  （参见 [[TF-IDF词项加权|TF-IDF 词项加权]]）。
- 过滤效果与预期不符时，模型表现变化容易被错误归因到其他环节——因为很难想到去查停用词表与分词器的口径。
- 原文没有给出该残留对分类指标影响的数字，后果的量化程度未知。

## 修复规则
1. 停用词表必须在与 tokenizer 相同的预处理与分词之后生成或校验（原文要求：停用词表要与向量化器
   经过同样的预处理与分词）。
2. 换 tokenizer / analyzer 时重新校验停用词表，不能沿用旧表。
3. 不要迷信通用停用词表：原文指出流行清单可能包含对特定任务高信息量的词（点名 "computer"）；
   风格、人格类分类任务不应去停用词。
4. 交付前做一次交集检查：对样本文档跑 `build_analyzer()`，把输出与停用词表取交集，验证过滤命中符合预期。

## 验证状态
- 有缺陷（原文记录）：原文把该不一致明确列为需要提防的错误用法，并给出 "we've → we + ve" 的具体例子，
  还说明向量化器会对此类不一致给出警告；本卡即依据该记录建立。
- 未给出数字：原文没有量化这种残留对分类效果的影响，也没有给修复前后的对比实验。
