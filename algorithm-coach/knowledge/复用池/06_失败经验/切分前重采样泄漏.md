# 切分前重采样泄漏

## 错误模式

类别不平衡时先对**全量**特征与标签做过采样（SMOTE / RandomOverSampler），再切训练/测试。合成样本由其近邻生成，会同时落在训练段与测试段，使测试集包含训练信息的衍生品。伴生错误：对时间序列使用 SMOTE，合成样本破坏时序结构与自相关，且不做时序切分。

## 触发场景

- 表格分类流水线"填充 → 编码 → 异常值 → 变换 → **SMOTE** → 缩放 → train_test_split"（10-2-04 的固定顺序）。
- 价格涨跌二分类先 `RandomOverSampler` 再按位置切 75/25（29-3）。
- 时间序列目标含 `shift(-1)` 后再对训练集 SMOTE（12-4），合成样本跨期混入新时序点。

## 如何识别

1. 检索 `SMOTE(` / `fit_resample(` / `RandomOverSampler(` / `resample()` 的调用位置：若在 `train_test_split` 或按日期切分之前，即泄漏。
2. 检查切分前样本量与切分后样本量是否守恒：如果测试集样本数明显大于原始数据中该段的真实记录数，说明合成样本进了测试集（29-3：重采样后训练 3633 行、测试 1211 行）。
3. 时间序列任务里出现任何形式的插值/合成式重采样，直接判为高危。
4. 检查是否"先重采样再 split，但只对训练段 refit"——顺序错了，后续任何补救都无效。

## 后果

- 测试集被污染，分类指标不可采信：29-3 的 0.49/0.50 准确率因此无效（原文仍据此下结论）。
- 合成样本进入测试段后，测试集不再代表真实类别分布，模型选择偏向能拟合合成模式的模型。
- 时序 SMOTE 生成的样本破坏自相关与波动聚集，使模型在真实序列上无对应模式可学（12-4 原文未讨论该风险）。

## 修复规则

1. **先切分，后重采样**：按时间或随机切出 train/test 之后，只对训练段 `fit_resample`；测试段保持原始分布永不重采样（12-4 在训练集内做 SMOTE 这一步方向正确，缺的是时序合理性校验）。
2. **时序任务不用 SMOTE**：改用类权重（`class_weight` / `scale_pos_weight`）、按时间的窗口采样、或调整标签阈值；确需过采样时按时间块采样而非按样本插值。
3. **切分后立即断言**：训练/测试索引不重叠、测试集行数等于原始测试段行数、测试集类别分布等于原始分布。
4. **在切分前预留验证集**（12-4 明确指出未做），避免"测试集既当评估又当早停"。
5. 若任务本身是截面数据（非时序），允许随机切分，但仍须遵守"先切分后重采样"。

## 验证状态

无一篇给出修复后的对照结果。29-3 报出 accuracy 0.49（max_depth=3）、0.50（max_depth=7/15），10-2-04 未给任何评估数值；这些数字均建立在被污染的测试集上，只能作为反面样本，不能作为方法性能证据。29-3 与 10-2-04 属代码顺序明确写错（自证错误），12-4 属风险未讨论（沉默性缺陷）。
