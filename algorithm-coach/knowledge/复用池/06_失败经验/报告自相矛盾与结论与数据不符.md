# 报告自相矛盾与结论与数据不符

## 错误模式

同一份材料内部，数字与数字、文字与代码、结论与证据之间存在无法并存的矛盾。这是**最值钱的一类失败经验**——它说明原文的结论未经复核，按原文结论复用会直接踩坑。可归为四型：

1. **数值互相矛盾**：正文 AIC −4506.06 vs 拟合摘要 −3506.28（观测数 712 vs 总记录 891）；网格选出 `reg_lambda=0.1` 与最终训练用 0.8；正文"夏普比率最高（0.953%）"与权重表 0.8496；`rf_rate` 在模拟循环为 0.0、在 `negativeSR` 内为 0.025。
2. **描述与代码/实现不符**：标题"9 层 MLP"实际只有 3 个 Dense；正文频率 `'D'` 代码写 `'W'`；训练 A2C 却用 DDPG 预测；summary 标题 ARIMA(2,5,1) 而代码标注 ARMA(2,0,1)；变量名 `std` 实际存的是方差。
3. **结论与数据不符**：accuracy 0.55、类别 0 召回 0.33 却称"稳定性"提升；"出现明显过拟合且训练/测试错误率趋于一致"（逻辑上趋同更接近欠拟合）。
4. **归因错误**：第二模型损失暴增最可能源于大盘指数量纲未处理，原文却归为"加入该特征无益"。

## 触发场景

- 手抄实验数值到正文，与代码输出脱节（AIC、夏普、参数）。
- 网格搜索结果与最终 `fit` 调用不一致（29-4）。
- 模型在网络结构/族/频率上被替换后，标题与说明未同步更新（14-5、11-4-3、8-4-3、4-2-02）。
- 数据处理流程与诊断结论冲突（ADF 在 5% 水平已判定对数价格平稳 P=0.0238，却仍继续做去滚动均值处理，理由未说明；对已去均值序列再做 5 阶差分属过度差分）。
- 输出合理性未做常识检查（R²=1.000、F-statistic=1.94e+34 仍被采信）。

## 如何识别

1. **抽取所有数值做一张对照表**：把正文数字与代码输出/表格数值并排列出，逐个核对。矛盾一旦出现，该篇所有数值都降级为"待复核"。
2. **参数取最终 `fit` 调用为准**：网格最优结果与最终训练参数必须一致；不一致时以实际训练为准，但该篇结论不可采信。
3. **结构性描述与代码互查**：层数、模型族、频率、训练算法、变量语义。
4. **输出合理性硬门槛**：R² ≥ 0.999、F 统计量 ≥ 1e30、MSE ≈ 1e-16、损失在 1e-3 以下且目标是价格水平——一律先排查，不允许直接采信。
5. **逻辑自检**：把结论转成一句可证伪的话，与数据对照（"误差趋同"→ 训练/测试误差接近 → 更接近欠拟合而非过拟合）。
6. **归因检查**：当某个特征/变量导致指标剧烈变化时，先排查量纲、缺失、对齐，再谈特征价值（5-3 的教训）。

## 后果

- 复现结果与报告不符，且无法判断哪个数字是对的。
- 错误归因导致错误的方法结论：把量纲问题误判为"特征无用"，会永久删掉有效特征。
- 结论与数据反向时，读者会按错误方向做决策（如按"稳定性提升"选择一个 recall 0.33 的模型）。

## 修复规则

1. **单一来源**：正文数值必须来自代码输出（`print`/表格导出）或自动生成，禁止手抄。
2. **参数一致性检查**：最终训练参数必须等于调参产出的 `best_params`，或在报告中显式说明差异原因。
3. **描述与实现同步**：模型结构、频率、算法、变量语义变更后同步更新标题、说明与变量名；`var()` 的结果不要命名为 `std`（13-3、14-3 的反例）。
4. **合理性门槛前置**：把 R²、F、损失量级、指标取值范围写成自动断言；触发即中止并回溯。
5. **结论必须可对照**：每条结论后附支撑数值与其口径，禁止"稳定性提升""拟合很好"这类无数值支撑的表述。
6. **回归检查**：正文"超预期/极端波动"的描述必须与程序输出（被标记的异常数、清洗前后差异）一致，不一致即视为未生效。

## 验证状态

本卡全部条目均为**原文自相矛盾/明显做错**，而非作者自述局限，具体证据：

- 1-2-3：正文称最优阶数 (1,0) 对应 AIC −4506.06，拟合摘要中 ARIMA(1,0,0) 的 AIC 为 −3506.28，观测数 712 与 891 条总记录不一致；常数项系数 0.0006、p=0.437 不显著。
- 29-4：GridSearchCV 结果为 max_depth=25、reg_lambda=0.1，实际训练用 max_depth=25、learning_rate=0.1、reg_lambda=0.8。
- 14-5：标题"9 层 MLP" vs 代码 3 个 Dense 层（`Dense(8*n_steps, relu)` → `Dense(64, relu)` → `Dense(32, sigmoid)`）。
- 4-2-02：summary 标题为 ARIMA(2,5,1)、代码块标注 ARMA(2,0,1)；ADF P=0.0238 已判平稳仍做去滚动均值与 5 阶差分。
- (8-1)：R-squared=1.000、F-statistic=1.94e+34，据此得到的 β 与 0.07% 年化预期回报不可信。
- 29-3：原文称"模型出现了过拟合现象，并且训练集和测试集的错误率趋于一致"，二者逻辑矛盾。
- 8-4-3：训练 A2C 却用 DDPG 预测，配置不一致；测试期负收益、夏普 −0.366 未分析原因。
- 9-6：开头称 2019-01-01 起有 1,000,000 美元初始资本，实际交易区间却是 `data_split(df,'2020-07-01','2021-10-31')`。
- 11-4-3：正文称频率为 'D'（每日）而代码写 'W'（每周），预测 30 步的含义随之不同。
- 8-5-6：`rf_rate` 0.0 与 0.025 不同源；正文 0.953% 与权重表 0.8496 不符；`max_sharpe_port` 变量前文未定义。
- 8-5-5：正文写 β"通常考虑过去 5 年数据"，输出标注"Beta (10Y period)"；夏普 0.53 被说成"53% 的超额年回报"。
- 5-3：损失降到 1e-16 被当作拟合极好；第二模型损失暴增被归为"加入该特征无益"。
- 6-3-01：称预测目标为波动率，但示例 target 含负值（2.31、-8.22），与波动率非负定义不符。
- (12-1)：标题写"期货交易策略"，摘要却称开发了"股票交易策略"。
- (3-3)AI金融实战：代码缺失，"随机森林"与"梯度提升树"前后不一致，实际模型无法确认。
- 13-3 / 14-3：`Roll_Stats` 把 `var()` 的结果命名为 `_std`。
