# 测试集参与调参与模型选择

## 错误模式

测试集被当作验证集使用，参与超参数搜索、早停、特征解释或模型筛选，导致报出的测试指标不再是独立样本外指标。识别标准很简单：**只要测试集的选择行为影响了任何一个建模决策，它就已被消费**。

## 触发场景

- **调参目标直接取测试集指标**：31-7 用 `objective(trial)` 返回测试集 ROC-AUC，`n_trials=1000`，无嵌套验证。
- **权重/超参在测试集上择优**：31-8-01 的集成权重 `trial.suggest_float` 以测试集 Accuracy 为目标函数。
- **测试集进早停**：29-4 的 `eval_set=[(X_train,y_train),(X_test,y_test)]` 配 `early_stopping_rounds=10`；1-2-7 直接把测试集当 `validation_data`；15-7 用测试集充当验证集观察 loss/val_loss 并据此选模型。
- **测试集做特征解释**：12-5 在测试集上算 `permutation_importance(n_repeats=100)`，若后续按重要性再筛特征即二次泄漏。
- **评估函数充当筛选器**：11-3-7 的评估函数直接用测试集做模型筛选。
- **在固定测试集上反复调特征**：3-2 的特征筛选评估用固定测试集，形成选择偏差。

## 如何识别

1. 搜索 `X_test` / `y_test` 出现的所有位置：除最终一次评估外，任何出现在 `fit`、`eval_set`、`objective`、`best_params` 决策路径上的都应剔除。
2. 检查是否存在三段：train / validation / test。只有两段（train/test）而又有调参行为，必然有一处用错。
3. 看调参日志的分数是否被直接当成最终性能：31-7 的 0.55/0.58 与 31-8-01 的 0.57/59.5% 都来自被调参消费过的测试集。
4. 检查早停回调是否绑定 `val_loss`，`val` 来自哪一段。
5. 检查同一测试集被评估的次数：一次为正常，多次择优即过拟合测试集。

## 后果

- 报出的指标系统性乐观，且无法估计乐观幅度：31-7 的 ROC-AUC 0.55~0.58、31-8-01 的 59.5% 都不是独立样本外结果。
- 模型选择结论不可靠：31-8-01 中 AUC 与 Accuracy 的排序互相矛盾（加权软投票准确率最好但 AUC 更低），加上两个指标都在测试集上消费过，无法判断哪个模型真的更好。
- 早停把测试段信息写回模型权重与训练轮数（29-4、1-2-7、15-7），使"测试集"名存实亡。

## 修复规则

1. **三段隔离**：train 调参、validation 早停与选模型、test 只评估一次、不做任何决策（31-8-01 明确指出"没有独立验证集"是问题所在）。
2. **嵌套验证**：外层留出测试集，内层用 CV 或滚动窗口做超参搜索，Optuna 的目标函数只能读内层数据。
3. **早停只用验证段**：`eval_set=[(X_val, y_val)]`；若必须监控训练损失，另外记录但不得用于 `restore_best_weights`。
4. **特征重要性只在训练段算**（12-5 的反例）；如需在整体上解释，须声明为事后解释、且不得回流到特征筛选。
5. **测试集使用次数记入报告**：写明"测试集仅在最终评估使用 1 次"。
6. **主指标在建模前唯一确定**，避免同一模型在两个指标下排序相反时无法裁决（31-8-01 的教训：必须统一主指标）。

## 验证状态

各篇均给出运行数值但未做隔离修正，因此均为被消费后的指标，只能作为反面样本：

- 31-7：HBGB 测试 AUC 由 0.51 提升至 0.55，CatBoost 由 0.51 提升至 0.58，1000 次试验，单次试验分数在约 0.47~0.55 波动。
- 31-8-01：硬投票 ROC-AUC 0.57，软投票与堆叠数值缺失；最优权重 HBGB 0.889、CatBoost 0.363，加权软投票测试准确率 59.5%。
- 29-4：测试集 1211 条，accuracy 0.55，类别 0 precision 0.71 / recall 0.33。
- 15-7：训练解释方差 0.9850、测试 0.9457（测试集充当验证集）。
