# 时序特征工程防泄漏约束

## 能力说明
金融时序特征工程必须在"只用截至上一期的信息"这一约束下完成。本卡把散落各篇的正确做法与已发生的泄漏案例收成一份审查清单。
用于在生成特征代码后自检：切分方式、指标计算口径、scaler 拟合范围、重采样顺序、阈值挑选位置。

## 输入契约
- 需要明确三件事才能开始审查：数据的时间列、决策时点（信号在 T 时刻生成）、特征窗口的定义区间。
- 需要能定位到具体实现位置：特征构造函数、scaler 拟合行、训练/测试切分语句、重采样与阈值搜索语句。
- 参考规模（用于判断泄漏影响）：31-4 AAPL 周频 1752 行；12-3 训练 465 周；15-6 BTC 504 条；1-2-7 单只 A 股日频。

## 输出契约
- 审查结论按四条检查项给出"合规 / 违规 / 未说明"，并指出违规点所在函数或语句。
- 合规判据（各篇给出的正确写法）：
  1. 切分：按时间点硬切，训练段严格早于测试段；交叉验证用 `TimeSeriesSplit(n_splits=5)`，不得用随机 K 折。
  2. 特征计算：滚动统计与技术指标先 `shift(1)`；特征函数对 train 与 test 分别调用，滚动指标各自重新起算。
  3. 缩放：scaler 只在训练段 `fit`，测试段只 `transform`。
  4. 标签对齐与重采样：标签 `shift(-1)` 与特征 `shift(1)` 必须同时成立；重采样只作用于训练段。
- 违规样本（可在代码审查时作为反例匹配）：
  - 全量数据上做特征选择/相关性筛选（3-2）。
  - 全量价格做标准化/归一化后再切分（15-6、3-3）。
  - 在测试集上算 permutation_importance 并据此筛特征（12-5）。
  - 先重采样再按位置切分（29-3）。
  - 全序列 rolling 出指标后再切窗（1-2-7）。
  - 在测试集上挑信号阈值（12-6）。

## 调用方式
按顺序执行以下断言式检查（每条都对应原文一处真实踩坑）：
```python
# 1) 切分先于一切
assert train.index.max() < test.index.min()          # 31-4/31-5：按日期切，禁止随机划分
cv = TimeSeriesSplit(n_splits=5)                     # 31-5

# 2) 指标只用历史
df_feat = raw.shift(1)                               # 14-3：所有滚动统计与技术指标计算前统一 shift(1)
close_to_ema8_ratio 用的 lag=2 应早于决策日           # 13-3：统计量在预测日前 2 天及更早计算
train_feat = new_features(train); test_feat = new_features(test)   # 12-3：两侧分别调用、各自起算

# 3) scaler 只 fit 训练段
sc.fit(train[cols]); X_test = sc.transform(test[cols])            # 11-3-5 的正确纪律

# 4) 标签与信号对齐
target = ratio_le_threshold.shift(-1); target.dropna()            # 12-4
position = sign.shift(1); model_returns = position * returns      # 12-6
```
- 审查重点还包括：`dropna()` 造成的样本损失要统计（31-5）；`add_diff` 前两行补 0 属伪数据会污染最前两期（14-3）。

## 关键参数
- `TimeSeriesSplit(n_splits=5)`；切分点示例：31-4 训练段 2014-01-01 之前、测试段 2014-01-01 至 2023-07-24；12-3 按年份硬切 2002–2012 / 2013–2023。
- `shift(1)`：特征侧统一滞后一期；`shift(-1)`：标签侧后移一期。
- 滚动窗口与滞后的最小取值须与决策时点一致（13-3 固定 lag=2）。
- 原文未给出验证集比例的统一定论：31-4 称验证集一般占 20%–30%，同时又说本篇实际只做 train/test 二划分，口径前后不一致。

## 依赖
pandas（shift、rolling、diff）；sklearn（TimeSeriesSplit、StandardScaler/MinMaxScaler）；imbalanced-learn（SMOTE / RandomOverSampler，用于确认重采样位置）。

## 适用条件
- 任何以历史数据预测未来的监督式特征工程，尤其是滚动指标、滚动窗口统计、滞后特征密集的管线。
- 复现他人 notebook 时做代码审计：本卡列出的违规形态在语料中反复出现。
- 多标的、多频率混合管线（FinRL 类）中确认标准化与状态构造是否对齐到同一决策时点（9-3 指出协方差与收益率序列是否对齐未说明，存在时序错位风险）。

## 不适用条件
- 本卡不是可直接调用的函数，不产出特征或模型；不能当作特征构造方案使用。
- 截面任务（同一时点多标的、无时间预测目标）的泄漏形态不同，本清单不覆盖。
- 文中所有合规写法都来自示例代码，原文并未做过泄漏对效果的量化对比，不能据此估算违规带来的收益虚高幅度。

## 验证状态
- 本卡记录的是语料中已发生的缺陷，全部为原文自述或原文实现中的实际问题：
  - 3-2：特征筛选在全部数据上做相关性计算、评估用固定测试集，未按时间切分，存在前视偏差与选择偏差。
  - 3-3：直接对全量数据变换会造成信息泄漏，原文未说明。
  - 12-5：在测试集上计算 permutation_importance 并据此解释特征，若后续按重要性再筛特征会造成信息泄露。
  - 12-6：阈值 0.607 在同一段测试集上挑出，存在阈值选择偏差。
  - 15-6：归一化在切分前对全量 504 条 `fit_transform`，测试段参与 scaler 参数估计，存在轻微泄漏。
  - 29-3：先用 RandomOverSampler 再按位置切分训练/测试，合成样本会同时进入两侧，测试集被污染。
  - 1-2-7：MA20/RSI/Momentum 在全序列上 rolling 后再切窗，窗口边界处的指标含未来信息；且直接把测试集当 validation_data 用于早停与学习率调整。
  - 9-3：标准化方式未说明（preprocess_data 内部实现未给出），若使用全样本统计量会引入前视偏差。
  - 12-4：对时间序列使用 SMOTE 会合成破坏时序结构的样本，原文未讨论该风险。
  - 5-3：未说明训练/测试切分方式（属未说明项）。
