# 类别分布漂移的问题分类与应对框架

## 能力说明

当测试期的类别集合可能与训练期不同（新话题、新意图、新实体类型出现）时，先把问题归入 KKC/KUC/UKC/UUC 四类之一，再据此选择监督、背景类、零样本或开放集框架，并按对应协议构造评测集；避免用闭集分类器硬扛未知类。

## 输入契约

- 训练期已知的类别清单与标注情况：哪些类有标注样本、哪些类只有样本没有标签、哪些类只有类名没有样本、是否会出现完全未知的类。
- 可用的辅助资源：是否有离群/背景语料（OOD 集）、是否有类名或类描述等语义先验、是否有无标签的目标域文本。
- 评测预算：能预留多少类作未知类、能否做多档已知/未知比例的重复实验。

## 输出契约

- 问题归类（KKC / KUC / UKC / UUC）与对应框架选择（标准监督 / 背景类 / 零样本 / 开放集学习与发现）的书面说明。
- 按选定框架改造的评测集：预留类清单、已知:未知类比例档位、测试时要求的判定粒度（只判"开放空间"还是要归类）。
- 该框架已知失效条件的清单（如背景类依赖辅助数据质量、零样本依赖类名措辞、开放集阈值不可估计）。

## 调用方式

1. 判定漂移类型：新类是否已知（有类名）？是否有样本（有标签/无标签）？据此落到四类之一。
2. 选框架：有标注的已知类走监督；有样本无标签的类走背景/Universum 类（用 Entropic/Objectosphere/能量/outlier exposure 一类损失，需 OOD 辅助数据）；类名已知无样本走零样本（蕴含式提示或类原型对比学习）；完全未知的类走开放集（检测 + 可选发现）。
3. 构造评测：从标准分类数据集预留 2/4/6 个类作 UUC，训练时完全不使用其标签；已知:未知比例设 25%/50%/75% 等多档做敏感性；注意 100% 已知类时模型仍可能判出开放空间，不等价于闭集。
4. 检查失效条件：背景类方法确认辅助数据覆盖度；零样本固定类名措辞并测试措辞敏感性；开放集方法明确阈值来源（离群因子或两阶段检测）。
5. 如需持续适应，把新类发现接到增量更新流程（检测异常 → 挖掘候选话题 → 零样本命名与归类 → 回训），但要预期这一环在文本域尚无成熟框架。

## 关键参数

- 四类定义与对应问题：KKC → 标准监督；KUC → 背景/Universum 类；UKC → 零样本；UUC → 开放集学习与发现。
- 框架能力对照（原文表 2）：只有开放集支持"类集合无界"与"开放世界假设"；背景类需要 OOD 训练数据；零样本不需要 OOD 数据但不能处理 UUC；开放集被标为"难以优化"。
- 联合目标权重设定：背景类 α>0（β=γ=0）；零样本 β>0（α=γ=0）；开放集 γ>0（α=β=0）。
- 常用评测语料及规模：AG News 127k/4 类、DBPedia 630k/14、20 Newsgroup 18k/20、Yahoo! Answers 1.4m/10、SST-2 69k/2、IMDb 50k/2、Amazon Product Reviews 50k/50、TMNtitle 32.6k/7、R21578title 10.8k/90。
- 开放集预留比例档位：已知类占比 100% / 75% / 50% / 25%（文献中还见"预留 2、4、6 个类"的做法）。
- 零样本改造：dev 与 test 都含全部类（如 Yahoo! Answers dev 6k/类、test 10k/类），另设"标签部分可见"（平衡划分）与"标签完全不可见"（无训练集）两种变体。

## 依赖

- 需要离群检测组件（LOF、ABOF2、Isolation Forest 等）、聚类组件（k-means）或能量模型/典型性检验来实现开放集与发现。
- 需要语义先验（类名/类描述）与能做蕴含判断的模型来实现零样本路线。
- 评测依赖标准分类语料的重划脚本；无现成的漂移版数据集分发。

## 适用条件

- 部署环境会出现训练期未覆盖的新类别（话题随时间变化的新闻/评论、意图不断新增的对话系统、实体类型扩展的 NER）。
- 需要为这类场景设计评测协议（预留未知类、比例扫描）时。
- 已知标注数据不足、需要借助语义先验或辅助 OOD 数据时。

## 不适用条件

- 类别集合封闭、测试分布与训练一致时不必引入本卡，用普通闭集评测即可（引入会无故抬高复杂度）。
- 只有"背景漂移"（语气、立场变化）而没有新类出现时，不应把样本判为开放空间——那会把已知类样本在分类前就拒掉。
- 原文为综述、无自跑实验，本卡不能作为效果承诺使用；要落地必须先在自己的语料上验证。

## 验证状态

原文为综述，未给出自跑实验数字；其数据统计（语料规模与适用设定）、框架能力对照表与评测协议均来自对已发表工作的归纳。因此本卡标为待验证：方法可用，但具体效果需在目标语料上自行验证。
