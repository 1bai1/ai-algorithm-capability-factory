# 时序切分与滚动验证

## 能力说明
为时序预测与策略回测提供不泄漏未来信息的训练-验证-测试协议：按时间顺序切分、扩窗滚动（walk-forward）重估、交叉验证按折报告与折间方差判读。解决"指标看起来很好但样本外崩坏"这个环节的问题。

## 输入契约
- 带可排序时间索引的单序列或多特征表（日频/周频/小时频均可），含目标列与特征列；特征必须只使用当期及更早信息（如全特征 shift(1) 后再入模）。
- 最小样本量：原文未给出统一门槛。实例规模参考：周频 504 条（15-6，训练 352/测试 152）、日频 762 条（15-10，训练 533/测试 229）、日频 4637 条（29-5 从第 1000 行起回测）、小时级 27812 条（27-4）。
- 缩放器、填充统计量、重采样器等需要数据拟合的步骤，必须在切分后仅用训练段拟合；原文多篇实例未做到，属反面参照。

## 输出契约
- 静态切分：train/test 两个 DataFrame，train 时间段严格早于 test，索引连续无打乱。
- 滚动验证：按测试段拼接的预测表（含真实值与预测值两列、日期索引），可直接用于分段指标与错误分布分析。
- 交叉验证：按折评分表，关键列 rank、mean_test、split_test、mean_train、split_train、mean_fit_time、mean_score_time、params；参数列需转字符串并设为索引后转置，一行一个配置便于横向比较。

## 调用方式
- 静态切分（按日期）：`train = df[df.index.year < 2020]`、`test = df[df.index.year >= 2020]`；或按位置 `threshold = int(X.shape[0] * 0.75)` 后切片。禁止 shuffle。
- 扩窗滚动回测（分类/回归模型）：`backtest(data, model, predictors, start=1000, step=50)`——每轮 `train=data.iloc[0:i]`、`test=data.iloc[i:i+step]`，i 递增 step，每轮只训练历史段。
- 单步 walk-forward（时间序列模型）：`walk_forward_validation(n_train, test)`——每步用 `log_df.iloc[:n_train+i]` 重训、只预测一步，输出 forecast / lower_interval / upper_interval 并与测试索引对齐。
- 交叉验证：GreyKite 的 `run_forecast_config` 内部自动做 K 折（日志与 split_* 列显示 3 折），用 `summarize_grid_search_results(grid_search=..., decimals=2, cv_report_metrics=None, column_order=[...])` 汇总。
- 反例警示：`GridSearchCV(cv=3)`（29-4）、`RandomizedSearchCV(cv=10)`（11-3-7）与单次留出（其他多篇）都未使用 TimeSeriesSplit，不能直接照搬到时序任务。

## 关键参数
- 训练/测试比例：70/30（15-10、15-6）、75/25（29-6-02）、8:2（GARCH 波动率实例）；验证集一般占数据集 20%–30%（31-4 给出的原则）。
- 滚动回测起点与步长：start=1000 行、step=50 行（29-5）。
- GreyKite：forecast_horizon=30、coverage=0.95，默认 3 折（11-4-3）。
- 随机种子需固定：seed=123（31-6）、random_state=42（12-5）、random_state=23（11-3-7）。
- 原文未给出：最小样本量门槛、walk-forward 重估频率上限、判定"折间方差过大"的量化阈值（原文只用"折间差异极大"定性）。

## 依赖
pandas、numpy；scikit-learn（切分与指标）；GreyKite（run_forecast_config / summarize_grid_search_results）；statsmodels 或 pmdarima（walk-forward 中每步重估的模型）。

## 适用条件
- 单标的或小规模多标的、日频及以上、样本量数百条以上，且需要样本外泛化估计时。
- 模型训练成本允许反复重估：ARIMA(5,0,5) 每期重估 169 次约 2 分钟（15-12），成本需提前估算。
- 需要区分"欠拟合/过拟合"时：同时看 mean_train 与 mean_test，训练折误差也高说明精度不足而非过拟合。

## 不适用条件
- 样本过短时不要做多折 CV：504 条（15-6）、169 个交易日（15-12）这类规模下折内统计不稳定。
- 交叉验证不能替代回测，也不能只看均值：11-4-4 的 mean_test_MAPE=60.13 对应三折 116.93 / 34.5 / 28.96，折间方差极大时单看排名会掩盖"模型对时间段高度敏感"；应改为按市场状态/时间段分段评估。
- 上游已污染时任何切分协议都失效：29-3 在切分前用 RandomOverSampler 过采样（合成样本同时进入训练与测试，测试集被污染，accuracy 0.49~0.50 不可信）；27-4 直接 `val_data = train_df`；29-4 把测试集放进 early stopping 的 eval_set；31-7 用测试集 ROC-AUC 作 Optuna 目标函数；11-3-7 用测试集做模型筛选。这些实例的指标只能当观测值，不能当泛化证据。
- 归一化/标准化在全量数据上 fit 再切分会泄漏：15-6 的 MinMaxScaler 在切分前对全量 504 条 fit_transform；29-6-01 同样在全量上 fit。
- 一次性留出切分不能用来评估"随时间演化"的策略，需要滚动重估才能贴近实盘（29-6-02 仅做一次 75/25 留出）。

## 验证状态
原文给出真实运行结果，属已验证：
- 11-4-4（比特币价格预测，GreyKite，3 折）：mean_test_MAPE=60.13、mean_train_MAPE=73.62，三折测试 MAPE 分别 116.93 / 34.5 / 28.96，mean_fit_time=12.56s、mean_score_time=0.86s。
- 15-6（BTC 周频，2020-09-13 起共 504 条，70/30=352/152）：线性回归测试 MAE 0.0247 / RMSE 0.0320，XGBoost 0.0474 / 0.0610，随机森林居中；R² 训练约 0.988、测试约 0.952（该值主要来自价格强自相关，原文未与朴素基线对比）。
- 29-6-02（(4624, 13, 13) 输入，75/25=3468/1156）：测试 MSE=0.003459。
- 29-5（GOOG 日频，滚动扩窗 start=1000、step=50）：回测有效样本 3637 行，精确率由 67.83% 提升到 85.28%。
上述数字反映的是"协议被这样用过"，其中多篇的防泄漏处理不完整（见不适用条件），采纳时需自行补齐。
