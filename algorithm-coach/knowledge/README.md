# 行业算法能力知识库

本目录是 Algorithm Coach 的知识库，也是一个可直接由 Obsidian 打开的 vault。
采用「原始池 → 提炼池 → 复用池 → 任务池」的闭环结构，服务于目标场景算法的
检索、生成、验证与沉淀。

**当前知识库为空**（本分支从零建库）。四池的分工与写权限见仓库根目录 `AGENTS.md`
的「知识库结构」与「角色与写权限」两节。

## 目录分层

- `原始池/`：未经整理的原始材料，按来源类型分目录（线上博客、论文与官方文档、行业书籍、原始代码、数据源说明、实验记录）。付费课程原文不随仓库分发，仅本地保留。
- `提炼池/`：从原始池逐份筛选、提炼后的内容；**目录结构与原始池一一对应**，便于追溯。
- `复用池/`：把提炼内容组织成 Agent 可直接检索、判断、生成和验证的能力卡；分类目录是场景相关的，见 `AGENTS.md`。
- `任务池/`：某一次具体任务的输入、生成代码、验证结果和报告。
- `知识库索引.md`：复用池全部卡片的清单，含 status 与一句话描述。由 `../scripts/gen_knowledge_index.py`
  从卡片 frontmatter 生成，**不要手工编辑**；复用池增删卡片后重跑该脚本即可同步。
  **只有复用池里有卡片时才会生成**——空库不产出索引。

## 使用原则

1. 原始材料先进入 `原始池/`，不要直接当作已验证知识使用。
2. 提炼池与原始池保持同构，只做筛选、摘要、结构化和来源标注，不改变材料归属。
3. 复用池从提炼池中抽取可执行能力，用于模型选择、代码生成、验证和修复。
4. 每次运行只写入 `任务池/` 的新任务目录，不覆盖历史结果。
5. 验证成功或失败后，再把证据和经验回写到能力库（由知识管理员执行）。

## 能力卡之间的边

卡片之间的语义边写在卡末 `## 相关能力` 一节，格式固定为「边型 + 链接 + 一句判断依据」：

```text
- 常见误用：[[停用词表与分词器不一致|停用词表与分词器不一致]] —— 停用词表与分词器口径错位会让过滤与 IDF 双双失真，是本卡记录的错误示范
```

`——` 之后那句话是**判断依据**，它的作用是让每条边都可以被反驳。审边的时候先看这句话。

链接目标是**裸文件名**（不含 `.md`、不含 `/`），显示名等于目标卡片的 `name`。
不能用 `[[复用池/<类目>/<文件名>|...]]` 这种带路径的写法——卡片分散在子目录而边跨类目，
带路径的写法在 VS Code 的 Markdown Preview Enhanced 里会按「相对当前笔记所在目录」解析，
指向不存在的位置：点不开，**Ctrl+点击还会在当前目录新建空文件**。
裸文件名在 MPE 的 `shortest` 模式与 Obsidian 下都能按名字命中。

MPE 需要一处配置（已放在工作区设置里）：

```jsonc
// .vscode/settings.json
"markdown-preview-enhanced.wikiLinkResolution": "shortest"
```

详见 `知识图谱schema.md` 第 6 节。

### 边的可信度分级

边的依据强度递减，审边时按这个顺序判断：

1. **共同原文**（最强）：两张卡的 `sources` 字段有交集，说明讲的是同一个实验。可用脚本验证。
2. **流程阶段**（中等）：「模型必须有上游特征」这类关系是结构性推断，不是这批材料独有的事实。
3. **方法类比**（最弱）：两卡解决同一类问题但无共同原文，属于判断而非证据，不可当证据使用。

判断一条边属于哪类，看 `——` 后面那句话：说得出具体数字或文件的是可核实的；
只说「两者都做同一件事」的是判断。

### 连边标准

只有一条：**这条边对「该不该用这个能力、怎么用」有没有决策价值。**

于是具体、会导致出错的依赖连边；泛泛、常识性的依赖不连。例如「特征工程需要原始数据」
是常识，不会因为看到这条边就改变做法。**相邻不等于有决策依赖。**
