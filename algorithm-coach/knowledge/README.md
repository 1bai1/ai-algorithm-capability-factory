# 量化算法能力知识库

本目录是 Algorithm Coach 的行业知识库，也是一个可直接由 Obsidian 打开的 vault。
知识库采用“原始池 -> 提炼池 -> 复用池 -> 任务池”的闭环结构，服务于量化股票预测算法的检索、生成、验证和沉淀。

## 目录分层

- `原始池/`：未经整理的原始材料，按来源类型分目录（线上博客、论文与官方文档、量化书籍、原始代码、数据源说明、实验记录）。线上博客的课程原文属付费内容，不随仓库分发，仅本地保留。
- `提炼池/`：从原始池逐份筛选、提炼后的内容；目录结构与原始池保持一致，便于追溯。
- `复用池/`：把提炼内容组织成 Agent 可直接检索、判断、生成和验证的量化能力结构，共 92 张能力卡，分七类。
- `任务池/`：某一次具体股票预测任务的输入、生成代码、验证结果和报告。
- `知识库索引.md`：复用池全部卡片的清单，含 status 与一句话描述。由 `../scripts/gen_knowledge_index.py` 从卡片 frontmatter 生成，**不要手工编辑**；复用池增删卡片后重跑该脚本即可同步。

## 使用原则

1. 原始材料先进入 `原始池/`，不要直接当作已验证知识使用。
2. 提炼池与原始池保持同构，只做筛选、摘要、结构化和来源标注，不改变材料归属。
3. 复用池从提炼池中抽取可执行能力，用于模型选择、代码生成、验证和修复。
4. 每次运行只写入 `任务池/` 的新任务目录，不覆盖历史结果。
5. 验证成功或失败后，再将证据和经验回写到提炼池，并在复用池更新可执行能力。
6. Markdown 是事实来源，Obsidian 负责浏览、反向链接和图谱展示。

## 能力卡之间的边

复用池的 92 张卡之间共 **452 条语义边**，每条边写在卡片末尾的 `## 相关能力` 一节里，
格式固定为「边型 + 链接 + 一句判断依据」：

```text
- 常见误用：[[复用池/06_失败经验/缺失值填充错误|缺失值填充错误]] —— 跨标的整列均值填充（AAPL/TSLA 被填成 1066.48）与连续缺失插值伪数据都是本卡记录的错误示范
```

`——` 之后那句话是**判断依据**，它的作用是让每条边都可以被反驳。审边的时候先看这句话。

### 五种边型

| 边型 | 对应关系 | 条数 |
|---|---|---|
| 常见误用 | 用错了会怎样 | 178 |
| 上游依赖 | 我需要谁产出 | 94 |
| 实证证据 | 这能力在真实标的上跑出过什么 | 83 |
| 下游用途 | 谁需要我产出 | 60 |
| 并列/替代 | 同一问题有两条路，要选 | 37 |

前两者构成流程链，后三者构成决策依据。所以这张图实际上是两张图叠在一起：
一张流程依赖图，一张证据与风险图。

### 同一个大类内怎么连：四种依据

以 `01_数据获取与处理`（内部 16 条边）为例。这 16 条边不是一条直线，而是**以取数为枢纽的一张小型依赖图**：
取数向下接复权与对齐，快照、采集容错、字段契约横挂在取数上，体检与平稳化各是一条短支链。

**一、环节内部的子步骤顺序**

```text
Tushare A股行情与新闻数据接入 --[下游用途]--> 交易日对齐与多源数据合并
  依据：本卡取回的个股行情、大盘指数与同花顺新闻是 date+ticker 对齐合并的原始输入
```

判断方式：读 Tushare 卡的**输出契约**（个股 OHLCV + 大盘指数 + 新闻），
再读对齐卡的**输入契约**（把多来源数据按 date+tic 合并），两边契约对得上就连边，
方向从产出的指向消费的。

```text
行情降采样与频率统一 --[下游用途]--> 价格序列平稳化（对数、差分与ADF检验）
  依据：差分要求等间隔无缺口序列，本卡按自然日推进的等间隔构造是其前置
```

注意这里连的是 `降采样` 而不是 `数据质量体检`——体检卡的下游是风险建模，
并不通向平稳化。**边的方向按实际契约定，不按想象中的工序顺序定。**

**二、同类替代品**

```text
Tushare A股行情与新闻数据接入 --[并列/替代]--> yfinance 美股与加密行情接入
yfinance 美股与加密行情接入 --[并列/替代]--> Tushare A股行情与新闻数据接入
  依据：A股与美股/加密两条取数路线，按标的所属市场二选一，代码体系与复权规则不可混用
```

两张卡解决同一件事，但**适用条件互斥**。注意这里是**两条方向相反的边**（各自独立写了一条），
不是一条双向边——图谱里从哪张卡进入都能走出去。全库共有 121 对这样的互为邻居关系。
这类边告诉使用者：按标的市场二选一，别一起用。

**三、共享一个前置**

```text
数据快照与可复现性约定 --[上游依赖]--> Tushare A股行情与新闻数据接入
  依据：快照链路的起点：取数一次即落盘（maotai_stock_data.csv 891 条），后续脚本只读本地
```

快照卡自己**不取数**，它规定的是“取数结果怎么落盘”，所以它必然挂在某个被约定的对象上。
同理，`行情采集容错、限速与增量更新` 与 `行情字段契约与多标的面板组织` 也都挂到取数卡上——
它们都是**包在取数动作外面的工程约定**，不产出数据，只约束数据怎么取、怎么存、长什么样。

**四、这张卡记录的坑**

```text
数据质量体检与缺失值处理 --[常见误用]--> 缺失值填充错误
  依据：跨标的整列均值填充（AAPL/TSLA 被填成 1066.48）与连续缺失插值伪数据都是本卡记录的错误示范
```

这类边的依据是**共同原文**：失败卡里那个反例就是从这张卡的原文提取出来的。
同一份材料，一个正向讲怎么做、一个反向讲做错了会怎样，所以连边。

### 跨大类怎么连：产出物被消费，且消费错了会出事

`01` 与 `02` 之间只有 3 条边，全部列出：

```text
复权口径与复权价选用 --[下游用途]--> 预测标签构造
  依据：未来N期收益标签必须建立在复权价口径上，否则除权日会造出假收益

技术指标与量价特征构造 --[上游依赖]--> 复权口径与复权价选用
  依据：均线类指标一律用 Adj Close 计算，复权口径决定整套指标取值是否正确

标准化与归一化 --[上游依赖]--> 数据质量体检与缺失值处理
  依据：缺失值先处理，否则 scaler 的统计量会被 NaN 污染
```

- 第一条：`预测标签构造` 要算 `log(close_{t+N}/close_t)`，价格若未复权，除权日会凭空造出假收益。
- 第二条：均线必须用复权收盘价，混用 `Close` 与 `Adj Close` 会让指标本身出错。
- 第三条：数据里还有 NaN 时，scaler 的统计量会被污染。

三条边的共同特征：**都是“如果不知道对方，就会做错”的依赖**，不是“流程上相邻”。

### 边界：什么不连

连边标准只有一条：**这条边对“该不该用这个能力、怎么用”有没有决策价值。**

于是具体、会导致出错的依赖连了边；泛泛、常识性的依赖被删掉。例如
`标准化 → 价格序列平稳化` 这类候选边在成稿时被剔除，理由是太泛——
“特征工程需要行情数据”是常识，不会因为看到这条边就改变做法。

代价是：从一张特征卡进入时，不会被引导回数据层的卡。实际检索从索引开始，
索引里各类并列，影响不大。

### 七个大类的“性格”

| 类别 | 内部边 | 跨类边 | 内部占比 |
|---|---|---|---|
| 01_数据获取与处理 | 16 | 23 | 41% |
| 05_回测系统与风险评估 | 14 | 51 | 22% |
| 02_高级特征工程 | 8 | 31 | 21% |
| 04_交易策略 | 8 | 39 | 17% |
| 03_预测模型 | 11 | 61 | 15% |
| 06_失败经验 | 5 | 81 | 6% |
| 07_验证证据 | 4 | 100 | 4% |

- **01 内部最密（41%）**：数据处理是一条真正的流水线，工序之间有实实在在的依赖。
- **02 内部最疏**：特征卡彼此独立，“算 MACD”和“算情绪因子”之间没什么话说，价值在于各自与模型、数据的连接。
- **06 与 07 几乎全是跨类边（94%、96%）**：它们是**元数据层**，存在的意义就是指向别的类别。
  失败经验卡不跟失败经验卡说话，它去警告模型和特征；证据卡不跟证据卡说话，它去给模型作证。

因此 `03↔07` 之间边最密（39 条）——课程里每个模型都有对应的真实案例，模型卡与证据卡是天然配对。
而 `01↔02` 这种“工序相邻”的关系反而稀：**相邻不等于有决策依赖**。

### 图里信息量最大的一处

入度最高的 12 张卡中有 7 张来自 `06_失败经验`，全部标着「有缺陷」。
全图最大的单一流向是 `07_验证证据 → 06_失败经验`（53 条）——证据卡记录的真实结果里，
相当一部分是失败的实证。所以这张图最密集的地方不是“最好的能力”，而是“最容易犯的错”。

### 边的可信度分级

边的依据强度递减，审边时按这个顺序判断：

1. **共同原文**（最强）：两张卡的 `sources` 字段有交集，说明讲的是同一个实验。可用脚本验证。
2. **流程阶段**（中等）：“模型必须有上游特征”这类关系是结构性推断，不是这批材料独有的事实。
3. **方法类比**（最弱）：两卡解决同一类问题但无共同原文，属于判断而非证据，不可当证据使用。

判断一条边属于哪类，看 `——` 后面那句话：说得出具体数字或文件的是可核实的；
只说“两者都做同一件事”的是判断。
