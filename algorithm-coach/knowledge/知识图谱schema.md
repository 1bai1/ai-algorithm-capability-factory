# 知识图谱 Schema

本文件说明**复用池那张图是怎么设计的**：节点是什么、边怎么连、哪些写法算合法、
以及为什么这么定。给三种人看——写卡的人（知识管理员）、改结构的人、维护校验器的人。

「合法」的最终裁决者是 `../scripts/validate_knowledge.py`（它是可执行的，带 29 类违规
夹具自测）。本文件是它的人读版，两者不一致时**以脚本为准**。

## 1. 设计目标

要解决的问题：**让"能力知识"能被机器检索、被校验、被复用。**

由此推出三条约束：

- **结构可查**——节点是谁、边怎么连、状态与溯源，要能被程序直接读，不能藏在文章里；
- **内容可读**——卡片正文是散文，给人读、给 agent 按章节改；
- **一个字段只有一个权威方**——同一个事实不写两遍，否则迟早对不上。

## 2. 权威划分：结构与内容分离

复用池里只有两个本体：

| 本体 | 文件 | 管什么 |
|---|---|---|
| **结构本体** | `复用池/nodes.csv`、`复用池/edges.csv` | 节点是谁、边怎么连、状态与溯源 |
| **内容本体** | `复用池/<类目>/<id>.md` | 卡片正文：标题 + 各章节的散文 |

由此推出三条硬规矩：

1. **卡片正文里不许出现结构**——没有 frontmatter，也没有「相关能力」小节。
   出现这两样，校验按错误处理（那是迁移没做干净）。
2. **两张 CSV 里不许出现散文**——只有标量字段，散文一律留在卡片里。
3. **派生物不许手工编辑**——`knowledge/README.md`（目录导航 + 卡片清单）由
   `../scripts/gen_knowledge_index.py` 生成；`复用池/graph.html`（可交互图谱）由
   `../scripts/render_graph.py` 生成、且不进仓库。改了复用池就重跑。

**为什么这么分**：早先结构与正文耦合在每张卡片里（边写在卡末、字段写在 frontmatter），
后果有三——agent 要遍历图就得把整张卡读进上下文（一张 3–6k 字符，走两跳要开 19 个
文件、5.5 万字符），所以它只能"读索引猜 1–3 张卡"；解析器只抓得到卡片内容的一个子集
（边的判断依据根本抓不到，少东西还不报错）；图没法交给别的工具。

### 对齐规约（"两个本体"的直接后果）

两边必须一一对应——这是分家之后最容易烂的地方：

1. `nodes.csv` 每行的 `category/id.md` 必须真实存在
2. `复用池/<类目>/` 下每个 `.md` 必须在 `nodes.csv` 里有对应行
3. 表里的 `category` 必须与文件所在目录一致
4. 卡片 id 在**整个工作区内唯一**（`knowledge/README.md` 里的 `[[id|标题]]` 按名字匹配）

**提示级**：提炼池里有文件没被任何卡片的 `sources` 引用时，会提醒一句（孤儿素材）。

## 3. 节点：一张能力卡

`nodes.csv` 的四个列：

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | 键 | **卡片文件名去掉 `.md`**；唯一、非空、不含空格与 `/` |
| `category` | 枚举 | 七类之一（见下），且必须等于文件所在目录名 |
| `status` | 枚举 | `已验证` / `待验证` / `有缺陷` |
| `sources` | 多值 | 分号 `;` 分隔；每项以 `提炼池/` 开头，且指向真实存在的文件 |

**文件路径 = `复用池/<category>/<id>.md`**——能推出来的东西不存，少一列就少一处漂移。

**没有 `name` 列**：展示名就是正文的一级标题，id 与标题不要求一致。

七个类目：

```
01_数据获取与处理   02_高级特征工程   03_建模方法   04_决策与应用
05_评估与稳健性     06_失败经验       07_验证证据
```

（这七个是**当前场景**的分类体系；换场景时改本文件、`validate_knowledge.py` 与
`gen_knowledge_index.py` 里的同一个常量，以及两个测试文件。）

**真例子**（`nodes.csv` 的一行）：

```csv
TF-IDF词项加权,02_高级特征工程,已验证,提炼池/线上博客/文本分类专题/scikit-learn_文本特征提取文档.md;提炼池/线上博客/csdn/csdncopy.md
```

### 本节规约

1. `id` 唯一、非空、不含空格与 `/`、不带 `.md`
2. `category` 必须是那七类之一
3. `status` 必须是 `已验证` / `待验证` / `有缺陷` 之一
4. `sources` 非空，每项以 `提炼池/` 开头且文件真实存在

**提示级**：连接特别多的"枢纽卡"（度数 ≥ 14）会被提醒——改它影响面大。

## 4. 边：能力之间的关系

`edges.csv` 的四个列：

| 列 | 类型 | 约束 |
|---|---|---|
| `from_id` | 外键 | 必须存在于 `nodes.csv` |
| `to_id` | 外键 | 必须存在于 `nodes.csv`；不得等于 `from_id` |
| `type` | 枚举 | 四种之一，见下 |
| `reason` | 文本 | **非空且必须单行**——判断依据是这条边可被反驳的抓手 |

**排序约定**：nodes 按 `id` 排，edges 按 `(from_id, to_id, type)` 排。这样改一条边
就是一行 diff，不会整表抖动。

四种边型与方向约定（方向不是自由发挥，每种只有一个方向）：

| 边型 | 方向 | 说明 |
|---|---|---|
| `依赖` | from 在流水线上**先于** to | 表示、特征、模型、评估之间的先后 |
| `实证证据` | from 必须是 `07_验证证据` 的卡 | 证据卡 → 被它验证的能力 |
| `常见误用` | from 是被使用的能力，to 是已知的坑 | 通常是 `06_失败经验` 的卡；也可以是某张被误用的能力卡 |
| `并列替代` | **对称关系** | 按 id 字典序只存一条，查询时双向看 |

**真例子**（`edges.csv` 的一行）：

```csv
文本预处理与分词,词袋与N-gram文本表示,依赖,词袋的 tokenizer/analyzer 直接复用本环节产出，分词与归一化策略决定词表内容
```

### 本节规约

1. `type` 必须是那四种之一
2. `from_id` 与 `to_id` 都必须存在于 `nodes.csv`
3. 不允许自己连自己
4. `reason` 非空，且必须单行
5. 同一条边（起点 + 终点 + 类型）不许重复写
6. **不许"互指"**：同一对节点之间同类型只允许一条边
7. `实证证据` 的 `from_id` 必须是 `07_验证证据` 的卡
8. `并列替代` 必须按 id 字典序存（`from_id` ≤ `to_id`）
9. 每个节点至少有一条边（没有孤儿）

**为什么有第 6 条**：早先每张卡从自己的视角自述关系，同一个事实被写两遍（A 写"我的上游
是 B"、B 又写"我的下游是 A"），112 条边里只有 79 条是唯一事实。搬进 CSV 之后
"从我的视角"这个动机消失了，所以迁移时做了合并，并加了这条规矩防止再长出来。

## 5. 内容：卡片正文的章节结构

正文只留内容：一级标题 + 固定章节。

所有卡片都有的两个：

```
## 验证状态      原文是否给出真实运行结果（枚举值在 nodes.csv 的 status 列，这里写解释）
## 来源          逐条列出提炼池来源及各自贡献
```

**能力卡**（`01`–`05`、`07`）另含八节，顺序固定：

```
## 能力说明  ## 输入契约  ## 输出契约  ## 调用方式
## 关键参数  ## 依赖      ## 适用条件  ## 不适用条件
```

**失败模式卡**（`06`）另含五节，顺序固定：

```
## 错误模式  ## 触发场景  ## 如何识别  ## 后果  ## 修复规则
```

**真例子**（一张卡的开头）：

```markdown
# TF-IDF 词项加权

## 能力说明
在词频上乘逆文档频率：压低在所有文档里都高频出现的词、抬高只在少数文档出现的词……
```

### 本节规约

1. 有一级标题
2. `验证状态`、`来源` 各恰好出现 1 次
3. 按卡片类型，专属章节齐全（能力卡八节 / 失败模式卡五节），各恰好 1 次
4. `能力说明`（失败卡为 `错误模式`）正文不少于 20 字——空壳不算卡
5. 不残留 frontmatter
6. 不残留 `## 相关能力`

## 6. 设计取舍：为什么这么定

每条都写清"放弃了什么"——将来想改的时候，先看看当初为什么没这么选。

| 决定 | 放弃了什么 |
|---|---|
| 结构进 CSV、内容留 MD | 卡片不再自包含（读一张卡看不到它跟谁连着），换来"遍历不用开文件" |
| `id` 就是文件名 | 放弃语义化命名空间（`model.text.shallow` 那套），换来"改文件名不用重写边" |
| 不给 `nodes.csv` 加 `desc` 列 | 放弃"读模型自足"（不开卡就知道这张卡讲什么），换来"没有派生列可漂移" |
| `并列替代` 只存一条 | 放弃"两边都写更直观"，换来对称关系不重复 |
| 一张卡一个文件、不拆小节 | 放弃更细的粒度，换来"读一张卡就是读一个文件" |
| 不设 `updated` 日期列 | 没有东西维护它，加了就是迟早过期的字段 |
