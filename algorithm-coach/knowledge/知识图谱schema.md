# 能力知识图谱 Schema

本文件定义 `复用池/` 下知识图谱的**权威划分、节点与边的表结构、以及全部不变量**。
校验脚本 `../scripts/validate_knowledge.py` 按此文件执行检查（29 类违规夹具的自测在
`../tests/test_validate_knowledge.py`）。

## 1. 权威划分（最重要的一节）

复用池里只有两个权威方，**每个字段只归一个**：

| 本体 | 文件 | 管什么 |
|---|---|---|
| **结构本体** | `复用池/nodes.csv`、`复用池/edges.csv` | 节点是谁、边怎么连、状态与溯源 |
| **内容本体** | `复用池/<类目>/<id>.md` | 卡片正文：标题 + 各章节的散文 |

由此推出三条硬规矩：

1. **卡片正文里不许出现结构**——没有 frontmatter，也没有「相关能力」小节。
   正文里出现这两样，校验按错误处理（那是迁移没做干净）。
2. **CSV 里不许出现正文**——两张表只有标量字段，散文一律留在 MD。
3. **派生物一律不许手工编辑**——`知识库索引.md` 与 `graph.graphml` 由
   `../scripts/gen_knowledge_index.py` 生成，改了复用池就重跑脚本。

### 为什么要这么分

早先结构与正文耦合在每张卡片里，后果有三：agent 要遍历图就得把整张卡读进
上下文（一张 3–6k 字符，走两跳要开 19 个文件、5.5 万字符），所以它只能"读索引
猜 1–3 张卡"；解析器只抓得到卡片内容的一个子集（边的判断依据根本抓不到，少东西
还不报错）；图没法交给别的工具。分开之后：**遍历读两张表，只对选中的卡读正文**。

### 图谱在知识库中的位置

```text
原始池  （外部来源的原始材料，付费材料不进仓库）
   ↓ 逐份提炼
提炼池  （与原始池同构的提炼）
   ↓ 按能力重组
复用池  ← 知识图谱在这一层：结构在两张 CSV，内容在卡片 MD
   ↓ 任务产生的证据与教训
任务池
```

原始池与提炼池是**树**（目录即结构），复用池是**图**（节点靠边互联）。
本 schema 只描述这张图。

## 2. `nodes.csv`

表头固定为：

```csv
id,category,status,sources
```

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | 键 | **卡片文件名去掉 `.md`**；全局唯一、非空、不含空格与 `/`；同时决定文件路径 |
| `category` | enum | 七类之一（见下节），且必须等于文件所在目录名 |
| `status` | enum | `已验证` / `待验证` / `有缺陷` |
| `sources` | 多值 | 分号 `;` 分隔；每项以 `提炼池/` 开头，且指向真实存在的文件 |

**文件路径 = `复用池/<category>/<id>.md`**，不单独存 `file` 列——能推出来的东西不存，
少一列冗余就少一处能漂移的地方。

**没有 `name` 列**：展示名就是正文的 H1 标题。id 与 H1 不要求一致，也不强制同步。

### `category` 取值

```text
01_数据获取与处理
02_高级特征工程
03_建模方法
04_决策与应用
05_评估与稳健性
06_失败经验
07_验证证据
```

（这七个是**当前场景**的分类体系；换场景时同步改本文件、`validate_knowledge.py`
与 `gen_knowledge_index.py` 里的同一常量，以及两个测试文件。）

## 3. `edges.csv`

表头固定为：

```csv
from_id,to_id,type,reason
```

| 列 | 类型 | 约束 |
|---|---|---|
| `from_id` | 外键 | 必须存在于 `nodes.csv` |
| `to_id` | 外键 | 必须存在于 `nodes.csv`；不得等于 `from_id` |
| `type` | enum | 四种之一，见下 |
| `reason` | 文本 | **非空且必须单行**——判断依据是这条边可被反驳的抓手 |

排序约定：nodes 按 `id` 排，edges 按 `(from_id, to_id, type)` 排。这样改一条边
就是一行 diff，不会整表抖动。

### 四种边型与方向约定

方向不是自由发挥——每种边型只允许一个方向：

| 边型 | 方向 | 说明 |
|---|---|---|
| `依赖` | `from` 在流水线上**先于** `to`（上游 → 下游） | 表示、特征、模型、评估之间的先后 |
| `实证证据` | `from` 必须是 `07_验证证据` 的卡 | 证据卡 → 被它验证的能力 |
| `常见误用` | `from` 是被使用的能力，`to` 是已知的坑 | 通常是 `06_失败经验` 的卡；也可以是某张被误用的能力卡 |
| `并列替代` | **对称关系** | 按 `id` 字典序只存一条，查询时双向看 |

**为什么要有方向、又要合并**：早先每张卡从自己的视角自述关系，于是同一个事实被
写两遍（21 组镜像对：A 写"我的上游是 B"、B 又写"我的下游是 A"），112 条边里只有
79 条是唯一事实。搬进 CSV 之后"从我的视角"这个动机消失了，所以迁移时做了规范化，
并加了一条不变量：**同一对节点之间同类型只允许一条边，禁止互指对**。

`并列替代` 语义对称，存储却必须有向（避免每条存两遍），所以只存字典序在前的那条。
查询"谁和 X 并列"时要两个方向都看：

```python
edges[(edges.type == "并列替代") & ((edges.from_id == x) | (edges.to_id == x))]
```

## 4. 卡片正文的章节结构

正文只留内容。一级标题 + 固定章节：

所有卡片都有的两个章节：

```text
## 验证状态      原文是否给出真实运行结果（枚举值在 nodes.csv 的 status 列，这里写解释）
## 来源          逐条列出提炼池来源及各自贡献
```

**能力卡**（`01`–`05`、`07`）另含八个章节，顺序固定：

```text
## 能力说明  ## 输入契约  ## 输出契约  ## 调用方式
## 关键参数  ## 依赖      ## 适用条件  ## 不适用条件
```

**失败模式卡**（`06`）另含五个章节，顺序固定：

```text
## 错误模式  ## 触发场景  ## 如何识别  ## 后果  ## 修复规则
```

正文里**不得**出现 `## 相关能力`（边在 edges.csv）与 frontmatter（字段在 nodes.csv）。

## 5. 不变量

校验分三层，各管一段，互不越界。

### 内容层（读 MD）

1. 有一级标题
2. `验证状态`、`来源` 各恰好出现 1 次
3. 按卡片类型，专属章节齐全（能力卡八节 / 失败模式卡五节），各恰好 1 次
4. `能力说明`（失败卡为 `错误模式`）正文不少于 20 字——空壳不算卡
5. 不残留 frontmatter
6. 不残留 `## 相关能力`

### 结构层（读 CSV）

7. 两张表的表头与列数正确
8. `nodes.csv`：`id` 非空、唯一、不含空格与 `/`、不带 `.md`
9. `nodes.csv`：`category` ∈ 七类，`status` ∈ 三值
10. `nodes.csv`：`sources` 非空，每项以 `提炼池/` 开头，且文件真实存在
11. `edges.csv`：`type` ∈ 四种
12. `edges.csv`：`from_id` / `to_id` 均存在于 `nodes.csv`
13. `edges.csv`：不允许自指
14. `edges.csv`：`reason` 非空且单行
15. `edges.csv`：同一条边（from+to+type）不得重复
16. `edges.csv`：**禁止互指对**（同一对节点间同类型只准一条）
17. `edges.csv`：`实证证据` 的 `from` 必须是 `07_验证证据` 的卡
18. `edges.csv`：`并列替代` 必须按 `id` 字典序存（`from_id` ≤ `to_id`）
19. 每个节点至少有一条边（无孤儿）

### 对齐层（两边互查）

20. `nodes.csv` 每行的 `category/id.md` 必须真实存在
21. `复用池/<类目>/` 下每个 `.md` 必须在 `nodes.csv` 里有对应行
22. 表里的 `category` 必须与文件所在目录一致
23. 卡片 id 在整个工作区内唯一（索引里的 `[[id|标题]]` 按名字匹配）

### 警告级（只提示不阻断）

1. 节点度 ≥ 14——枢纽节点，改动影响面大
2. 提炼池里有文件没有被任何卡片的 `sources` 引用（孤儿素材）

## 6. 示例

`nodes.csv` 里的一行：

```csv
TF-IDF词项加权,02_高级特征工程,已验证,提炼池/线上博客/文本分类专题/scikit-learn_文本特征提取文档.md;提炼池/线上博客/csdn/csdncopy.md
```

`edges.csv` 里的一行：

```csv
文本预处理与分词,词袋与N-gram文本表示,依赖,词袋的 tokenizer/analyzer 直接复用本环节产出，分词与归一化策略决定词表内容
```

对应卡片 `复用池/02_高级特征工程/TF-IDF词项加权.md` 的开头：

```markdown
# TF-IDF 词项加权

## 能力说明
在词频上乘逆文档频率：压低在所有文档里都高频出现的词、抬高只在少数文档出现的词……
```

## 7. 扩展指引

**改结构一律走工具，不要手搓 CSV**：

```bash
python scripts/edit_graph.py check
python scripts/edit_graph.py add-edge 卡A 卡B 依赖 "B 在流水线上先于 A"
python scripts/edit_graph.py add-node 新卡 03_建模方法 待验证 提炼池/示例/来源.md
python scripts/edit_graph.py set-status 卡A 已验证
python scripts/edit_graph.py rename 卡A 卡A_v2      # 同时改文件、表行与所有引用它的边
python scripts/edit_graph.py del-edge 卡A 卡B 依赖
python scripts/edit_graph.py del-node 卡A
```

工具会在写盘前校验这次改动本身合不合法（枚举、外键、方向、互指对），
写完之后记得刷新派生物并跑一次全量校验：

```bash
python scripts/validate_knowledge.py            # 校验，输出摘要
python scripts/validate_knowledge.py -v         # 同时列出全部警告明细
python scripts/gen_knowledge_index.py           # 刷新索引与 graph.graphml
python tests/test_validate_knowledge.py         # 校验器自身的自测（29 类违规夹具）
```

**新增一张卡**：`add-node` 会生成骨架（标题 + 该类型应有的章节），补齐正文后
`add-edge` 连边。`sources` 必须指向提炼池里已存在的文件。

**新增一种边型**：改动面比想象的大——本文件第 3 节、`validate_knowledge.py` 的
`EDGE_TYPES`、`gen_knowledge_index.py` 的 `EDGE_TYPES` 与 `EDGE_TYPE_MEANING`、
两个测试文件。边型应当描述真实的语义关系，不要为了分类而分类。

**新增一类能力**：在 `复用池/` 下加目录并更新 `CATEGORIES` 常量（本文件、
两个脚本、两个测试文件）。七类是按当前业务划分的，扩类意味着图谱的语义层次变化，
不要随意增删。
