# 能力知识图谱 Schema

本文件定义 `复用池/` 下知识图谱的节点、字段、边与不变量。它是**对现状的描述**，
不是新拟的规范——下面每条规则都是从现有 92 张卡片中测量得出，校验脚本
`../scripts/validate_knowledge.py` 按此文件执行检查。

## 1. 图谱在知识库中的位置

知识库分四层，图谱只存在于最上层的**复用池**：

```text
原始池  （课程原文、论文、代码，本地图层）
   ↓ 逐份提炼
提炼池  （与原始池同构的 194 篇提炼）
   ↓ 按能力重组
复用池  ← 知识图谱在这一层：92 个节点、452 条边
   ↓ 任务产生的证据与教训
任务池
```

原始池与提炼池是**树**（目录即结构），复用池是**图**（节点靠边互联）。
本 schema 只描述这张图。

## 2. 节点类型

| 类型 | 所在目录 | 数量 | 判定方式 |
|---|---|---|---|
| 能力卡 CapabilityCard | `01`–`05`、`07` | 73 | 含「能力说明」等八个能力章节 |
| 失败模式卡 FailurePattern | `06_失败经验` | 19 | 含「错误模式」等五个失败章节 |
| 索引卡 IndexCard | `复用池/知识库索引.md` | 1 | frontmatter 含 `generated: true` |

索引卡由 `../scripts/gen_knowledge_index.py` 生成，**不手工编辑**，不参与下面的卡片校验。

## 3. 卡片文件名

文件名即**稳定标识符**，被边的路径部分引用，因此不含空格，多词用 `_` 连接：

```text
A股配对_协整检验与VAR建模.md
美元指数_与A股相关性分析.md
```

## 4. frontmatter 字段

五字段**全部必填**，当前 92/92 张齐备：

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | string | 全局唯一；点分命名空间，小写字母数字与 `._-`；段数 2–4（实测 3 段 62 张、2 段 28 张、4 段 2 张） |
| `name` | string | **展示名**，允许空格、`×`、`（）`、`/` 等排版符号；全局唯一 |
| `category` | enum | 必须等于所在目录名，取值见下节七类 |
| `status` | enum | 三值之一：`已验证` / `待验证` / `有缺陷` |
| `sources` | string[] | 非空；每项以 `提炼池/` 开头，且指向真实存在的文件 |

### `name` 与文件名的关系

**两者不要求一致**（实测 30 张不同）。文件名是标识符，`name` 是给人看的展示名：

```text
文件：IML锌价_ARMA月度预测.md
name：IMF锌价 × ARMA 月度预测
```

`name` 的排版自由，但必须全局唯一——边的显示名会引用它。

### `category` 取值

```text
01_数据获取与处理
02_高级特征工程
03_建模方法
04_决策与应用
05_评估与稳健性
06_失败经验
07_验证证据
```

（这七个是**当前场景**的分类体系；换场景时同步改本文件、两个脚本里的
同一常量与测试文件即可。）

## 5. 章节结构

一级标题 `##` 的集合按节点类型固定。三种章节**所有卡片都必有**：

```text
## 验证状态      原文是否给出真实运行结果
## 来源          逐条列出提炼池来源及各自贡献
## 相关能力      边的落点，见第 6 节
```

**能力卡**另含八个章节（顺序固定）：

```text
## 能力说明  ## 输入契约  ## 输出契约  ## 调用方式
## 关键参数  ## 依赖      ## 适用条件  ## 不适用条件
```

**失败模式卡**另含五个章节（顺序固定）：

```text
## 错误模式  ## 触发场景  ## 如何识别  ## 后果  ## 修复规则
```

当前 92/92 张完全符合，无缺章、无多章、无命名变体。

## 6. 边

### 书写格式

边写在卡片末尾 `## 相关能力` 一节，每行一条：

```text
- <边型>：[[<卡片文件名>|<显示名>]] —— <判断依据>
```

实例：

```text
- 常见误用：[[缺失值填充错误|缺失值填充错误]] —— 跨标的整列均值填充（AAPL/TSLA 被填成 1066.48）与连续缺失插值伪数据都是本卡记录的错误示范
```

- **链接目标必须是裸文件名**，不含 `.md`、不含任何 `/`。
- **显示名必须等于目标卡片的 `name` 字段**。此项为警告级，不阻断校验。
- **判断依据**必填，是这条边可被反驳的抓手。审边先看这句。

#### 为什么必须用裸文件名，以及编辑器要怎么配

链接必须写裸文件名，这一点由**解析器**决定，而不是写作习惯。当前有两个解析器会
处理这些链接，它们对 `[[X]]` 的解析方式不同：

| 解析器 | 默认行为 | 裸文件名能否命中 |
|---|---|---|
| Obsidian | 按文件名搜索整个 vault | 能 |
| VS Code + Markdown Preview Enhanced | `wikiLinkResolution` 默认 `relative`，**相对当前笔记所在目录**解析 | **不能** |

卡片分散在 `复用池/<类目>/` 下，而边几乎全部跨类目。在 MPE 的默认 `relative`
模式下，任何 `[[X]]` 都被指向「当前笔记所在目录 / X.md」——不存在，于是解析失败。
**失败的表现不只是点不开：在预览里 Ctrl+点击会在当前目录新建一个空文件**，
把知识库搞乱——曾出现过在类目目录里又套一层 `复用池/` 的错位目录。

修复方式是改 MPE 的解析方式：

```jsonc
// .vscode/settings.json
"markdown-preview-enhanced.wikiLinkResolution": "shortest"
```

MPE 的文档把 `shortest` 明确标注为「**Obsidian 风格**」——按文件名搜索所有笔记，
优先取最短唯一路径。改完两个解析器行为一致，裸文件名在两边都能命中。

另外两个取值：`relative` 是 MPE 默认，对本库不适用；`absolute` 从工作区根解析，
而本工作区根是 `akf`，卡片在其下多层，同样不适用。

因为 `shortest` 按名字匹配，**卡片文件名必须在整个工作区内唯一**（见不变量 14），
否则会产生歧义。

#### 在 Obsidian 里使用

Obsidian 按文件名搜索整个 vault，裸文件名直接可用。唯一要求是 **vault 根开在
`knowledge/` 这一层**，不要打开它的子目录——根设错了图谱只覆盖一部分。

### 五种边型

| 边型 | 方向语义 | 实测条数 |
|---|---|---|
| `上游依赖` | 我需要谁产出 | 94 |
| `下游用途` | 谁需要我产出 | 60 |
| `实证证据` | `07` 类为某能力提供真实运行结果 | 83 |
| `常见误用` | 该能力已知的错误用法 | 178 |
| `并列/替代` | 同一问题的另一条路线，需对比选择 | 37 |

边的连接依据分三个强度层级（共同原文 > 流程阶段 > 方法类比），详见 `README.md`。

## 7. 不变量

校验脚本按此清单检查。**错误级**违反即非零退出，**警告级**只提示。

### 错误级

1. frontmatter 完整，五个必需字段齐备
2. `status` ∈ {`已验证`, `待验证`, `有缺陷`}
3. `category` == 所在目录名
4. `id` 全局唯一且符合字符集
5. `name` 全局唯一
6. `sources` 非空，每项以 `提炼池/` 开头
7. `sources` 指向的文件真实存在（提炼池缺失时跳过此项）
8. `验证状态`、`来源`、`相关能力` 各恰好出现一次
9. 按节点类型，专属章节齐全（能力卡八节 / 失败模式卡五节）
10. 每条边符合书写格式，目标为裸文件名（不含 `/`）
11. 边的目标指向真实存在的卡片
12. 无自链接
13. 每张卡至少 1 条边
14. 卡片文件名在**整个 vault 内唯一**——这是裸文件名链接能无歧义解析的前提

### 警告级

1. 边的显示名不等于目标卡片的 `name`
2. 出度偏离实测区间（当前为 3–8）

## 9. 扩展指引

**新增一张卡**：按第 4、5 节建 frontmatter 与章节，`status` 取三个枚举值之一，
`sources` 指向提炼池中已存在的文件，然后在 `## 相关能力` 按第 6 节补 2–6 条边。
完成后跑一次校验脚本。

**新增一种边型**：需要同步改三处——本文件第 6 节、`README.md` 的边说明、
以及校验脚本的边型枚举。边型应当描述真实的语义关系，不要为了分类而分类。

**新增一类能力**：在 `复用池/` 下加目录并更新 `category` 枚举，同步更新索引生成脚本的
`CATEGORIES` 常量。七类是按当前业务划分的，扩类意味着图谱的语义层次变化，不要随意增删。

**校验**：

```bash
python scripts/validate_knowledge.py          # 校验，输出摘要
python scripts/validate_knowledge.py -v       # 同时列出全部警告明细
python tests/test_validate_knowledge.py       # 校验器自身的自测
```

校验器自身也经过验证：`tests/test_validate_knowledge.py` 会构造 14 类违规的夹具
（缺字段、枚举越界、类目不符、id 越界、重复 id/name、来源前缀错、来源文件不存在、
缺章节、失败卡缺章节、边格式错、边目标不存在、自链接、零边），逐条确认能被检出，
并确认检出错误时退出码为 1。夹具建在临时目录，不触碰真实知识库。
