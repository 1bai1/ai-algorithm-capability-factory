# 分析方案

## 能力选用（每个选择都指回卡片）

| 决策 | 依据卡 | status | 怎么用 |
|---|---|---|---|
| A 股日线取数 | `Tushare A股行情与新闻数据接入` | 已验证 | 字段契约（trade_date/OHLCV/amount）、取数即落盘。本任务因无 token 改用 baostock，字段向该卡对齐 |
| 列名与主键 | `行情字段契约与多标的面板组织` | 已验证 | 统一 `date` 为日期主键并转 datetime 排序；原始价 / 复权价分列，避免同名不同义 |
| 复权口径 | `复权口径与复权价选用` | 待验证 | 取数时显式要求前复权（baostock `adjustflag='2'`＝前复权），并另存一份不复权；收益率只用复权列 |

| 容错与限速 | `行情采集容错、限速与增量更新` | 待验证 | 查询带重试、取不到不中断整批、请求间 `sleep` 限速 |

## 复权口径对照（baostock）

| `adjustflag` | 含义 | 本任务用途 |
|---|---|---|
| `1` | 后复权 | 不使用 |
| `2` | 前复权 | `600519_daily_qfq.csv`，收益率/标签口径 |
| `3` | 不复权 | `600519_daily_raw.csv`，真实成交价口径 |

## 字段契约

**单标的主键**：`date`（datetime，升序，唯一）。

**原始价文件**：`date, code, open, high, low, close, preclose, volume, amount, turn, pctChg, peTTM, pbMRQ, psTTM, isST`
**前复权文件**：同字段，价格列已被前复权改写，`pctChg` 为除权日也连续的口径。
**合并面板**：`date` + 原始 `open/high/low/close` + `adj_open/adj_high/adj_low/adj_close` + `volume/amount/turn/pctChg`。
列名用 `adj_` 前缀显式区分口径，杜绝「同一列名不同含义」。

**指数文件**：`date, code, open, high, low, close, preclose, volume, amount, pctChg`（指数无换手/估值/ST 字段）。

## 校验协议（结构化 JSON）

脚本末尾对落盘结果逐项校验，输出 `validation/validation.json`，区分：

- `syntax_error`：脚本无法解析（本脚本由运行器捕获）
- `runtime_error`：取数或落盘抛异常
- `timeout`：运行超时
- `interface_violation`：字段契约不符（缺列 / 主键不唯一 / 未排序）
- `data_leak`：不适用（本任务只取数不建模）
- `metric_fail`：数据质量未达阈值（缺失、OHLC 逻辑冲突、复权与原始日期集合不一致等）

每个检查项给 `name / status(pass|fail) / detail / value`，并给出 `overall` 结论。
