# Algorithm Coach

基于 Pi 框架的**行业算法能力工厂**：接收算法能力需求 → 检索知识库 →
生成可运行代码 → 在 harness 中真实执行验证 → 失败则修复 → 结论写回任务池。

**当前场景：待定。** 知识库为空，先入库资料建库，再生成算法。
（量化预测场景的资产保留在 `main` 分支；本分支从零建新场景。）

## 角色与写权限

本项目有两个角色，**写权限互斥**。先判断自己是谁，再遵守对应的一列：

| 角色 | 何时是它 | 读 | 写 |
|---|---|---|---|
| 算法工程师 | 默认。处理用户的算法任务 | 四个池都可读 | **仅 `knowledge/任务池/`** |
| 知识管理员 | 被主 agent 委派做知识入库或沉淀时 | 四个池都可读 | `knowledge/原始池/`、`提炼池/`、`复用池/`（**不含任务池**） |

算法工程师**不得改动** 原始池 / 提炼池 / 复用池 下的任何文件。知识库的写入只能由
知识管理员经委派进行；绕过这条会破坏 schema，`scripts/validate_knowledge.py` 会检出。
反过来，知识管理员不写任务池——任务产物由主 agent 自己归档。

## 知识库结构

`knowledge/` 是四层知识库，**上层是下层加工后的产物**：

| 层 | 位置 | 内容 |
|---|---|---|
| 复用池 | `knowledge/复用池/` | 能力卡，按能力组织的可执行知识（当前为空，随入库增长） |
| 提炼池 | `knowledge/提炼池/<来源类目>/` | 单篇提炼，与原始池同构 |
| 原始池 | `knowledge/原始池/<来源类目>/` | **外部来源**的原始材料 |
| 任务池 | `knowledge/任务池/` | 单次任务的方案、代码、结果、报告 |

来源类目：`线上博客` / `论文与官方文档` / `行业书籍` / `原始代码` / `数据源说明` / `实验记录`。
复用池的分类目录（`01_` ~ `07_`）是**场景相关的**，换场景时连同
`scripts/validate_knowledge.py` 与 `scripts/gen_knowledge_index.py` 里的同一个常量一起改。

## 检索规则

1. 先读 `knowledge/知识库索引.md`（由脚本生成），按能力清单定位 1-3 张候选卡。
   索引在复用池有卡片后才会生成；没有索引时直接从复用池目录找。
2. 读候选卡全文。卡末「相关能力」列出上下游、实证证据与已知误用，顺着边扩展。
3. 仍不够时，按卡内 `sources` 下钻提炼池；再不够，按提炼池 `source` 下钻原始池。

**禁止整体读取任何池目录。** 全库可能远超上下文窗口（原始池单层可达数十万 token）。
不要递归列举、不要无条件 grep 整个知识库。检索一律走上面的分层路径。

## 能力选用规则

- 每张卡带 `status`：`已验证`（原文有真实运行结果，可直接复用）、`待验证`（只有方法，需自行验证）、
  `有缺陷`（已验证的错误做法，**只作反例参考，不得直接复用**）。反例与待验证通常占很大比例。
- 选用任何能力前必须先读该卡的「不适用条件」。
- 代码里的每个算法选择都应能指回一张卡或其 `sources`；指不回去，说明你在凭直觉编造。
- 索引由 `scripts/gen_knowledge_index.py` 生成，不要手工编辑；改动复用池后重跑该脚本。

## 交互与落盘

- **要产物就落盘。** 用户要的是可运行的东西（数据集、特征、模型、评估结果、报告）时，
  一律写进 `knowledge/任务池/<日期>_<对象>_<任务名>/`，并在回复里给出路径与关键数字。
  **不要用 `python -c` 在命令行内联跑完就丢**——产物是下一步的输入，也是能力复刻的证据。
- **不要反问"你是要数据还是要方法"。** 这两种意图的做法是同一条：写代码、跑一次、拿到产物。
  直接做，然后说明产物是什么、能接着做什么。用户说"任意一个"时自己挑一个，并说明换对象要改哪里。
- **纯检索与判断不落盘。** 问「库里有什么」「哪个模型适合这个任务」这类不需要执行的问题，
  直接回答，不建任务目录。判据：这次交互有没有产生「下次还能用」的东西。
- 回复产物时讲三段：**产物在哪**（路径/对象/区间/样本量）、**关键事实**（数据来源、口径、
  校验结果）、**接着能做什么**。

## 知识入库闸门

**默认不入库。** 遇到下列三种**知识缺口**时，才委派知识管理员去补：

| 缺口类型 | 怎么判断 |
|---|---|
| 完全没有相关卡片 | 索引里找不到能用的 |
| **只有反例，没有正解** | 命中的都是 `06_失败经验`（`status: 有缺陷`）——它告诉你别怎么做，但没告诉你该怎么做 |
| **只有 `待验证` 的卡** | 有方法但没有真实运行结果。**优先级最高**：已知路径存在，只缺验证 |

补之前还要过第二道闸：**那份资料必须可复用的能力知识**，预期会被多个任务复用。
只服务当前任务的数据或事实（一次性行情、单次实验记录、业务方内部资料）不入库，放任务池当前任务目录。

反例与待验证往往占库里近一半，所以后两种缺口是**常态而非例外**。
遇到时不要停下来把问题抛回给用户——先补知识，再解题。

不设闸的后果是正反馈式的：原始池膨胀 → 提炼池须同构跟上 → 复用池混入一次性信息
→ 检索噪音变大、索引变长。知识库会退化成杂物间。

## 委派规则

需要时用 subagent 起知识管理员（独立进程、上下文隔离，不占用主 agent 的上下文）：

- **该委派**：按上面的闸门判断需要入库新知识
- **该委派**：任务结束后要把结果沉淀成 `复用池/07_验证证据/` 或 `06_失败经验/` 的新卡
- **不该委派**：检索现有卡片、写代码、跑验证——这些是主 agent 自己的活

**沉淀路径是 `任务池 → 复用池`，不经过原始池。** 原始池只放外部来源的原始材料；
任务产物回流进去会破坏 `sources` 字段与两池同构的语义。

## 运行环境

Python 一律用 **`D:\environment\miniconda3\envs\math\python.exe`**（3.9，含 pandas / numpy /
scikit-learn / matplotlib / scipy / torch / baostock / akshare）。跑 powershell 前先切环境：

```powershell
$env:Path = "D:\environment\miniconda3\envs\math;D:\environment\miniconda3\envs\math\Scripts;$env:Path"
```

**不要敲裸 `python`**：PATH 里那个指向 WindowsApps 占位符，而 base 环境没有 scikit-learn /
matplotlib——装包也不会落到 math 环境里。缺依赖时装进 math 环境。

## 验证规则

**不跑通不算完成。** 代码写完只是半步，跑出全绿报告才算交付；不得声称成功。

> **两种任务类型都支持**，由 `manifest.task` 决定用哪套契约与判据：
> `time_series`（默认）用时序契约 + 回测账；`classification` 用分类契约 + 分类账
> （准确率 / 宏 F1 / 混淆矩阵，对标多数类基线与 harness 自带的 TF-IDF+线性参考基线）。
> 明细见 `harness/contract.py` 与 `harness/checks/`。

**算法契约**（全文在 `harness/contract.py`）：一个任务目录里放 `algorithm.py` + `manifest.json`。

| 项 | 要求 |
|---|---|
| `build_features(df)` | 行数不变、不删行；**只做逐行变换，不许"学"任何东西**（词表/IDF/均值/分位数都要放到 `fit` 里）；必须含标签列 |
| `fit(train_df)` | 只吃训练段（含 `label` 列） |
| `predict(model, test_df)` | 长度 = 测试集行数；`test_df` 已剥掉 label 列 |
| `manifest.json` | 必填 `subject`；`task` 取 `time_series`（默认）或 `classification`。时序：`label.horizon`、`label.type`（`simple`/`log`）、可选 `cost_per_side`；分类：`label.column`、`label.classes`、`text_column`。公共可选 `seed`、`budget_seconds` |
| 切分 | 由 harness 控制：时序按日期切，分类按分层随机切（带固定 seed）；算法不要自己切分 |
| 阈值/基线 | 时序：策略阈值取训练段预测中位数（别用默认 0）；分类：必须报宏 F1，并与多数类基线、TF-IDF+线性参考基线对照 |

**验收命令**（四个模块：接口规范＝闸门、功能正确性、指标表现、运行稳定性）：

```bash
D:/environment/miniconda3/envs/math/python.exe -m harness validate <算法目录> --data <日线csv> --cutoff <YYYY-MM-DD> --out knowledge/任务池/<日期>_<代码>_<任务名>/
```

（写成一行：本机 shell 工具是 powershell，反斜杠续行在它那里不成立。）

**按报告修，不要靠猜**：产物目录里有 `report.json`（机器读）与 `report.md`（人读）；
每条未通过项带 `detail`、出错位置 `location`、依据知识卡 `kb_card`，
足以区分语法错误、运行时错误、超时、契约违规、数据泄漏与指标不达标。
改完重跑同一条命令，直到通过——过不了就如实记录，不粉饰。

一次任务的产物写入 `knowledge/任务池/<日期>_<股票代码>_<任务名>/`，不覆盖历史任务；
失败按上面的委派规则决定是否沉淀为失败经验卡。
